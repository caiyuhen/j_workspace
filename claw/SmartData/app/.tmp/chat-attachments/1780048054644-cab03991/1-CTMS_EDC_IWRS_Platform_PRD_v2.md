## 1. 执行摘要

本产品是一套一体化的临床试验管理平台，整合 CTMS（临床试验管理系统）、EDC（电子数据采集系统）、IWRS（交互式随机化与药物供应管理系统）以及医生个人病历夹四大核心模块，并扩展 6 大增强模块：安全管理中心、系统集成模块、系统配置中心、数据验证工具、报告中心、数据导入导出服务。

系统采用微服务架构，底层数据库符合 CDISC 标准，支持拖拉拽式 eCRF 设计，实现从试验管理、数据采集、随机化到医生个人患者管理的端到端数字化解决方案。

**核心价值主张**：
- **一体化整合**：10 大功能模块共用数据库，消除数据孤岛，提升协作效率
- **标准合规**：底层数据模型符合 CDISC/SDTM 标准，确保数据质量与监管合规
- **灵活配置**：拖拉拽式表单设计，CDASH 标准字段库，快速响应研究需求
- **AI 赋能**：全流程 AI 辅助原型设计、代码开发、测试生成、部署运维，加速交付周期 50-70%
- **SaaS 化部署**：多租户架构，支持快速扩展与持续迭代
- **安全可控**：独立安全合规中心，符合 21 CFR Part 11、GDPR、HIPAA 等监管要求

## 2. 产品愿景与目标

### 2.1 愿景

成为全球领先的智能化临床试验数字化平台，通过技术手段降低临床试验成本、提升数据质量、加速新药上市，同时为医生提供便捷的患者管理工具，实现临床试验与日常医疗的深度融合。

### 2.2 目标（AI开发）

| 目标类型 | 具体指标 |
|---------|---------|
| **用户体验** | eCRF 表单设计时间（从需求到上线） |
| **数据质量** | 数据核查问题发现周期 |
| **合规性** | CDISC 标准符合率 |
| **效率提升** | 数据锁库前清理时间 |
| **成本节约** | 单试验系统实施成本 |
| **用户覆盖** | 支持并发试验数量 |
| **开发效率** | 代码生成率 |
| **测试覆盖** | 自动化测试覆盖率 |

### 2.3 非目标（Non-Goals）

1. **不涉及实验室 LIS 系统深度集成**：仅支持实验室数据导入，不提供完整的 LIS 功能
2. **不提供影像归档与通信（PACS）功能**：仅支持影像数据链接引用
3. **不支持电子签名证书颁发**：对接第三方 CA 机构，不自建 CA
4. **不提供统计分析功能**：仅支持 SDTM/ADaM 数据导出，统计分析由专业软件完成
5. **暂不支持移动端原生应用**：第一阶段采用响应式 Web 设计

**原因说明**：上述功能属于相邻领域或可由第三方专业工具更好实现，聚焦核心能力确保 v1.0 按时交付。

## 5. 功能模块详细设计

### 5.1 CTMS 模块（临床试验管理）

#### 5.1.1 试验项目管理

**功能描述**：管理临床试验的全生命周期，从方案启动到数据锁库。

**用户故事**：
- 作为**项目经理**，我希望创建试验项目并配置基本信息，以便启动临床试验
- 作为**研究者**，我希望查看试验的入组进度和数据录入状态，以便监控试验进展
- 作为**监查员**，我希望收到试验关键节点的提醒，以便及时跟进

**核心功能**：
1. **试验基本信息**
   - 试验编号、名称、方案版本
   - 试验类型（干预性/观察性）、设计（RCT/单臂）
   - 赞助商、主要研究者、伦理委员会
   - 试验状态（方案中/进行中/已完成/终止）

2. **研究中心管理**
   - 中心列表与状态（已签约/已激活/已关闭）
   - 中心联系人信息（PI、Sub-I、CRC）
   - 中心启动文档管理
   - 入组目标与实际入组数跟踪

3. **试验时间轴**
   - 关键里程碑（首例入组、末例访视、数据库锁库）
   - 计划日期 vs 实际日期对比
   - 延迟预警与原因记录

**验收标准**：
- [ ] 支持创建、编辑、查询、归档试验项目
- [ ] 支持至少 100 个并发试验
- [ ] 关键节点提醒提前 7 天触发
- [ ] 入组进度实时更新（延迟<1 分钟）

#### 5.1.2 工时管理系统

**功能描述**：记录和管理项目成员的工时投入，支持项目成本核算。

**用户故事**：
- 作为**CRC**，我希望快速填报每日工时，以便结算费用
- 作为**项目经理**，我希望查看项目总工时和成本，以便控制预算

**核心功能**：
1. **工时填报**
   - 按项目/任务分类记录工时
   - 支持按日/周/月维度填报
   - 工时类型（数据录入、质疑回复、监查访视等）
   - 支持批量导入（Excel）

2. **工时审批**
   - 多级审批流程（组长→项目经理→财务）
   - 审批意见与驳回原因
   - 审批历史记录

3. **工时报表**
   - 项目维度的总工时与成本
   - 人员维度的工时分布
   - 工时趋势分析（周/月/季度）

**验收标准**：
- [ ] 支持至少 1000 条/秒的工时记录写入
- [ ] 审批流程可配置（1-3 级）
- [ ] 工时报表导出 Excel/PDF
- [ ] 工时数据与财务系统对接（预留接口）

#### 5.1.3 eTMF 电子试验主文件

**功能描述**：管理临床试验文档，支持在线编辑、版本控制、审批流程。

**用户故事**：
- 作为**文档管理员**，我希望上传并分类试验文档，以便符合 GCP 归档要求
- 作为**监查员**，我希望在线查看文档最新版本，以便进行现场监查
- 作为**审计员**，我希望查看文档修改历史，以便审计追踪

**核心功能**：
1. **文档库结构**
   - 符合 TMF Reference Model 2.0 的文件夹结构
   - A-L 分类（A: 启动文件，B: 方案与修正案，C: 监管文档...）
   - 自定义文件夹与标签

2. **文档管理**
   - 支持格式：PDF、DOCX、XLSX、PPTX、图片、压缩包
   - 在线预览与编辑（集成 OnlyOffice/Collabora）
   - 版本控制（自动保存历史版本）
   - 文档审批流程（草案→审核→批准→归档）

3. **文档检索**
   - 全文检索（Elasticsearch）
   - 按试验/中心/文档类型/日期筛选
   - 高级搜索（多条件组合）

4. **审计追踪**
   - 记录所有文档操作（上传、下载、修改、删除）
   - 操作人、操作时间、IP 地址、操作原因
   - 符合 21 CFR Part 11 要求

**验收标准**：
- [ ] 支持单个文件最大 100MB
- [ ] 支持同时在线编辑（实时协作）
- [ ] 文档检索响应时间<500ms
- [ ] 审计追踪记录保留≥15 年（可配置）

### 5.2 EDC 模块（电子数据采集）

#### 5.2.1 拖拉拽式 eCRF 设计器

**功能描述**：可视化设计 eCRF 表单，自动匹配 CDASH 标准字段。

**用户故事**：
- 作为**数据管理员**，我希望通过拖拉拽快速设计 eCRF 表单，而不需要编写代码
- 作为**数据管理员**，我希望系统自动提示 CDASH 标准字段名，以确保数据标准化
- 作为**数据管理员**，我希望在设计时配置数据核查规则，以保证数据质量

**核心功能**：

1. **表单画布**
   - 分区段（Section）设计：人口学、入选标准、访视 1、访视 2...
   - 拖拽组件：文本框、数字框、下拉框、复选框、单选框、日期框、计算器字段
   - 组件属性配置：字段名、标签、必填、默认值、显示逻辑

2. **CDASH 标准字段库**
   ```typescript
   interface CDASH_Field {
     variableName: string;        // 标准字段名（如：AESEV）
     displayLabel: string;        // 中文标签（如：不良事件严重程度）
     domain: string;              // 所属域（如：AE）
     fieldType: FieldType;        // 字段类型（STRING/DATE/ENUM）
     allowedValues?: string[];    // 枚举值（如：["MILD", "MODERATE", "SEVERE"]）
     validationPattern?: string;  // 正则表达式
     sdtmMapping?: {
       domain: string;            // SDTM 域（如：AE）
       variable: string;          // SDTM 变量（如：ASEV）
     };
   }
   
   // 示例：不良事件严重程度字段
   const AESEV_Field: CDASH_Field = {
     variableName: "AESEV",
     displayLabel: "不良事件严重程度",
     domain: "AE",

       domain: "AE",
   ```

   ```typescript
   const AE_Mappings: SDTM_Mapping[] = [
     { sourceField: "AE_TERM", targetDomain: "AE", targetVariable: "AETERM" },
     { sourceField: "AE_SEV", targetDomain: "AE", targetVariable: "ASEV" },
   ```

   - 数据导入（异步执行，进度条显示）
   - 导入报告（成功数、失败数、失败原因）

3. **导入场景**
   - 患者基本信息批量导入
   - 历史数据迁移（从旧系统）
   - 实验室数据批量导入
   - 字典数据导入（医学词典、代码集）

**验收标准**：
- [ ] 支持至少 1 万条数据/次导入
- [ ] 导入失败数据可重试
- [ ] 导入过程可取消
- [ ] 导入记录保留 90 天

#### 5.10.2 数据导出

**功能描述**：支持多种格式导出，满足不同场景需求。

**核心功能**：

1. **导出格式**

## 6. 数据标准与合规要求

### 6.1 CDISC 标准

**SDTM（Study Data Tabulation Model）**：
- 域（Domain）：AE、CM、DS、LB、PM、SE、DM...
- 变量命名：域前缀 + 变量名（如：AETERM、AESEV）
- 日期格式：YYYY-MM-DD
- 编码值：是 (Y)/否 (N)/缺失 (?)

**CDASH（Clinical Data Acquisition Standards Harmonization）**：
- 变量命名规范（大写、下划线分隔）
- 标准字段库（生命体征、不良事件、用药记录...）
- 数据捕获最佳实践

**实施要求**：
- eCRF 字段命名遵循 CDASH 标准
- SDTM 映射配置可维护
- 导出数据通过 CDISC 验证工具（DVS）

### 6.2 21 CFR Part 11 合规

**电子记录与电子签名要求**：
- 审计追踪：记录所有创建、修改、删除操作
- 访问控制：基于角色的权限管理
- 电子签名：符合签名意图、签名含义要求
- 系统验证：40 章（验证总计划、URS、设计文档、测试报告...）

**实施要求**：
- 所有关键操作需要审计追踪
- 电子签名需要双因素认证
- 系统验证文档齐全
- 定期权限审查（每季度）

### 6.3 GDPR/HIPAA 合规

**数据隐私保护**：
- 患者知情同意
- 数据最小化原则
- 数据主体权利（访问、更正、删除）
- 数据泄露通知（72 小时内）

**实施要求**：
- 数据加密存储与传输
- 数据脱敏展示
- 患者授权管理
- 数据泄露应急预案
