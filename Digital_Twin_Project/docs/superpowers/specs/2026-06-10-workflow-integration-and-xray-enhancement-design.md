# 联调与X光增强设计

## 1. 背景

当前项目已经实现了三种工作流的基础版本：

1. `pdf_only`
2. `xray_only`
3. `multimodal`

现有系统已经具备：

- `report-gateway` 统一入口 `/workflow/analyze`
- `xray-analysis-service` 的基础图像读取与近似特征提取
- `simulation-service` 和 `visualization-service` 的后半段复用
- 前端统一工作流页面

但当前还存在两个明显缺口：

1. 尚未完成一次基于真实样本的三种工作流联调
2. X 光特征提取仍然偏粗糙，缺少前景提取、中轴线估计、图像质量评估等增强

此外，当前仓库中没有真实 `.dcm` 样本，因此本轮不能完成“真实 DICOM 样本联调”，只能完成：

- DICOM 代码路径增强
- 错误处理增强
- 等待用户后续提供真实 DICOM 样本后再做实测

## 2. 本轮目标

### 2.1 目标

- 启动 `9000-9005` 全套服务并完成健康检查
- 通过网关统一入口完成三种工作流的实际联调
- 使用现有真实 PDF / PNG / HEIC 样本完成工作流验证
- 提升 X 光分析服务的特征提取能力
- 增加图像质量评分、分析元信息和更稳的失败提示
- 保持现有三种工作流接口不变

### 2.2 非目标

- 不做临床级自动 Cobb 角测量
- 不做真实 DICOM 样本联调
- 不做 DICOM 序列三维重建
- 不新增第二套前端
- 不推翻现有网关/模拟/可视化主链路

## 3. 范围拆分

本轮工作分为两个紧耦合子目标，但仍在一个实现周期内完成：

## 4. 联调设计

### 4.1 服务启动

- `9000`: report-gateway

- `9002`: visualization-service

- `9005`: xray-analysis-service

### 4.2 联调入口

所有验证都通过统一接口完成：

- `POST /workflow/analyze`

不以单服务测试代替联调。

### 4.3 样本策略

#### PDF-only

选取一份现有真实 PDF 作为输入，验证：

- OCR 提取
- PDF 状态构造
- 模拟
- 可视化

#### X 光-only

优先选取现有冠状面 PNG 文件，验证：

- 图像读取
- X 光状态构造
- 模拟
- 可视化

#### Multimodal

- 1 份 PDF
- 1 张 X 光 PNG

验证轻量融合逻辑是否生效，并输出统一 `patient_state`。

### 4.4 联调成功标准

每种工作流都应满足：

- 网关返回 200
- `patient_state` 存在
- `patient_state.metrics` 完整
- `timeline` 被下游成功消费
- 返回 `evolution_chart_json`
- 前端可显示结果

## 5. X 光增强设计

### 5.1 当前问题

当前 `XRayAnalyzer` 主要使用：

- 全图平均亮度分布
- 简单振幅估计

该方法的局限是：

- 对背景干扰敏感
- 不能稳定反映脊柱中轴线
- 对图像方向和边缘噪声过于敏感
- 生成的 `coronal_offsets` 与 `cobb_angle` 解释性较弱

### 5.2 目标能力

增强后应具备：

- 更稳的前景区域提取
- 更合理的脊柱近似中轴线估计
- 更稳定的冠状面偏移计算
- 基于曲率变化的近似 Cobb 角估计
- 图像质量评分
- 分析元信息输出

## 6. X 光分析算法设计

### 6.1 输入阶段

支持以下格式：

- `.png`
- `.jpg`
- `.jpeg`
- `.dcm`
- `.heic` / `.heif`（若环境可读）

策略：

- PNG/JPG/JPEG：直接通过 Pillow 读取
- DICOM：通过 `pydicom` 读取像素矩阵
- HEIC：尝试通过 Pillow 已注册插件读取
- 若 HEIC 环境不支持，则返回明确错误并提示用户转换格式

### 6.2 预处理阶段

预处理包括：

1. 灰度化
2. 自动对比度增强
3. 强度归一化
4. 简单平滑去噪

目标是降低背景和曝光差异对后续特征的影响。

### 6.3 前景提取

使用轻量规则提取人体主前景区域：

- 基于亮度阈值或分位数确定候选区域
- 沿行和列统计高强度连续区
- 估算主躯干边界框
- 若无法稳定提取，则降低质量分并标记需要复核

### 6.4 中轴线估计

在前景区域内：

- 按行扫描有效像素
- 提取每一水平带的中心位置
- 对中心点序列做平滑
- 生成近似脊柱中轴线

这个中轴线用于：

- `coronal_offsets`
- 弯曲振幅
- 近似曲率

### 6.5 特征派生

#### coronal_offsets

根据中轴线相对图像中心的横向偏移生成。

#### sagittal_profile

当前没有真实侧位重建，因此采用：

- 若输入文件名或患者样本显示为矢状面，则以纵向轮廓变化生成近似 profile
- 若仅有冠状面图，则仍生成保守近似值并降低置信度

#### vertebral_rotation

不做真实旋转识别，而是根据局部偏移变化幅度生成工程近似值。

#### cobb_angle

采用中轴线的最大曲率区间和整体偏移幅度估计近似值，而不是简单均值振幅。

### 6.6 图像质量评分

新增：

- `image_quality_score`

评分依据包括：

- 对比度是否足够
- 前景提取是否稳定
- 中轴线采样点是否足够
- 图像尺寸是否合理

质量过低时：

- `review_required = true`

### 6.7 分析元信息

新增：

- `analysis_meta`

包含：

- `format`
- `width`
- `height`
- `foreground_detected`
- `centerline_points`
- `image_quality_score`
- `view_hint`

## 7. 数据模型变化

### 7.1 patient_state 增强

在当前结构基础上新增：

```json
{
  "image_quality_score": 0.78,
  "analysis_meta": {
    "format": ".png",
    "foreground_detected": true,
    "centerline_points": 17,
    "view_hint": "coronal"
  }
}
```

### 7.2 兼容性要求

新增字段必须是向后兼容的：

- 现有 `simulation-service` 不应依赖新字段
- 现有 `report-gateway` 和前端可选显示这些字段

## 8. HEIC 策略

仓库中存在大量 `HEIC` 样本，因此需要显式处理。

### 8.1 优先策略

若运行环境支持 HEIC 解码，则直接纳入 X 光流程。

### 8.2 降级策略

若环境不支持：

- 返回可读的 422 错误
- 错误中说明建议转换为 PNG/JPG 再上传

不允许出现无上下文的 500。

## 9. DICOM 策略

### 9.1 本轮可交付

本轮只做：

- DICOM 读取路径增强
- 更好的错误处理
- 若文件结构异常，返回明确错误

### 9.2 本轮不做

- 真实 DICOM 样本联调
- 设备兼容性验证
- 序列重建

### 9.3 后续入口

待用户提供真实 `.dcm` 样本后，再进行：

- 单样本验证
- 多样本兼容性验证
- DICOM 联调回归测试

## 10. 前端与结果展示

本轮不重做页面结构，只做必要增强：

- 继续使用现有统一工作流页面
- 在结果区域补充显示：
  - `data_source`
  - `image_quality_score`
  - `review_required`
- 当质量低或融合冲突时高亮提醒

## 11. 错误处理

### 11.1 联调错误

- 服务未启动：记录服务名和端口
- 网关依赖失败：返回明确下游来源
- 样本文件缺失：返回样本路径问题

### 11.2 X 光错误

- 不支持格式：400/422
- HEIC 不可解码：422，并给出转换建议
- DICOM 像素缺失：422
- 图像质量过差：不阻断流程，但标记 `review_required`

## 12. 测试策略

### 12.1 自动化测试

新增或扩展以下测试：

- X 光增强后特征提取测试
- HEIC / DICOM 错误处理测试
- 联调辅助脚本测试
- 网关响应结构回归测试

### 12.2 实际联调测试

执行三类真实样本联调：

- `pdf_only`
- `xray_only`
- `multimodal`

记录：

- 样本名称
- 返回状态
- 关键结果字段
- 是否需要复核

## 13. 风险

- HEIC 支持受运行环境影响较大
- 当前 X 光特征提取仍为工程估计，不应过度解释为临床结果
- 某些图片若裁剪严重或背景复杂，中心线估计可能不稳定

## 14. 交付标准

- 全套服务成功启动
- 三种工作流至少各有 1 个真实样本联调成功
- X 光分析输出新增质量分和元信息
- HEIC / DICOM 错误提示更清晰
- 文档中明确说明 DICOM 真实样本验证待后续补充
