# OMOP 医疗数据清洗与治理平台 — 统一需求拆解与分阶段建设计划

## 1. 核心业务目标
构建符合 OMOP CDM 标准的医疗数据清洗、归一化、映射、质控、治理一体化平台。解决多源异构医疗数据（API、CSV）到 OMOP CDM 的端到端 ETL+L 问题，实现数据流转的**可回溯**、**自动化优先**、**质量门槛控制**和**可扩展**。

## 2. 功能模块边界与数据流转逻辑

### 2.1 数据流转逻辑
医院数据源 (API/CSV) → 数据接入 → Raw Zone (原始数据留痕) → 数据剖析 → 数据清洗与归一化 (Staging) → OMOP 字段与概念映射 → 数据验证与质量评估 → OMOP CDM 发布库 → 治理与回溯。

### 2.2 核心功能模块边界
- **前端工作台**：Dashboard、数据源管理、数据接入与剖析、映射管理（字段+概念）、清洗规则配置、质量看板、数据血缘与回溯、系统治理与权限。
- **数据接入服务**：API 轮询、CSV 大文件分片解析、增量识别、Raw Zone 入库保存。
- **数据清洗服务**：空值、类型、单位、字典编码等的转换和规范化处理，生成 Staging 数据。
- **OMOP 映射服务**：Source-to-OMOP 表/字段级映射，基于 OHDSI 词汇表的术语/概念映射及专家审核流。
- **数据质量服务**：内置合规校验与 OHDSI DQD 质控规则，阻断不合格数据。
- **调度编排服务**：依赖 Airflow/Dagster 的 ETL DAG 管理及任务重跑机制。
- **回溯与治理服务**：RBAC/ABAC 权限模型、字段级脱敏、数据血缘图谱（基于Neo4j）、全链路版本及操作审计。

## 3. 非功能性需求
- **性能**：支持 GB 级文件切片上传与千万级数据转换，网络内网 10Gbps。
- **可靠性**：失败任务隔离且支持节点重跑，零停机部署，原始数据严格保护（不覆盖）。
- **安全性**：PIPL/HIPAA 合规，提供 L1-L3 三级脱敏策略，密码/凭证使用 KMS，操作全量审计。
- **架构**：前后端分离（React + FastAPI），基于 Docker 容器化微服务架构部署，计算层支持 SQL + Spark。

## 4. 模块依赖关系与交付顺序（分阶段迭代模式）

按照 MVP 模式分为三个建设阶段，每个阶段均能独立形成数据闭环并支持可验证部署：

### 阶段一 (MVP 1)：基础接入与 Staging 转换
**目标**：打通数据从源头到 OMOP 核心表（PERSON, VISIT, CONDITION 等）的端到端物理流转链路。
- **依赖关系**：基础设施搭建 -> 数据源管理 -> 基础接入引擎 -> 规则引擎基础 -> OMOP Staging 入库。
- **交付内容**：
  1. 项目及环境初始化（React + FastAPI + PostgreSQL）。
  2. 数据源管理模块（API 配置与 CSV 上传）。
  3. 数据接入引擎与 Raw Zone 存储能力。
  4. 基础的字段剖析与简单清洗规则。
  5. 核心 5 张表的结构映射。
  6. Airflow 基础调度。

### 阶段二 (MVP 2)：术语映射与全面质量评估
**目标**：提升数据的医学语义准确度和系统入库的可靠度。
- **依赖关系**：MVP1 数据基础 -> 词汇表导入 -> 映射推荐引擎 -> DQD 集成。
- **交付内容**：
  1. OHDSI 词汇表集成与本地扩展。
  2. 概念候选推荐引擎与人工复核审批流。
  3. 数据入库前内置规则与 DQD 深度集成，阻断异常批次。
  4. 质量仪表盘（Dashboard）。

### 阶段三 (MVP 3)：数据回溯、脱敏治理与开放 API
**目标**：满足研究级数据的合规要求及运维管理诉求。
- **依赖关系**：MVP1+MVP2 -> 血缘追踪引擎 -> 权限与脱敏中心 -> 开放接口。
- **交付内容**：
  1. 行级、字段级、批次级的数据血缘追踪（集成 Neo4j）。
  2. 敏感数据三级脱敏策略实现。
  3. RBAC/ABAC 权限体系与完整审计日志。
  4. 提供对外的 OMOP 数据查询 OpenAPI。

## 5. 开发规范与测试驱动 (TDD)
- **前端 TDD**：使用 Jest + React Testing Library，先编写组件渲染、交互事件及接口 Mock 测试，再开发 UI 视图。
- **后端 TDD**：使用 Pytest，先编写 Controller 层的 API 测试与 Service 层的业务逻辑单元测试，再实现 FastAPI 接口及 SQLAlchemy 模型。
- **持续集成**：每完成一个模块（如“数据源注册”），必须保证测试覆盖率（语句级）达到 100%，并通过 CI/CD 流水线验证。
