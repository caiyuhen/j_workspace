# 医学专业智能体协同系统设计方案

**版本**: 1.0.0  
**日期**: 2024年1月  
**文档类型**: 系统设计文档

---

## 文档概述

本文档设计一个云端SaaS服务的医学专业智能体协同系统，覆盖临床诊断辅助、医学研究分析、健康咨询问答等全部场景，采用8个专业代理协同工作，支持skillhub.cn和MCP双协议集成。

**核心特性：**
- 大模型服务（192.168.0.214:8802/chat/）已**内置RAG（检索增强生成）能力**，包含医学知识向量库，无需单独设计知识库系统
- 多代理协同架构，智能任务分解与调度
- 双协议Skill集成（skillhub.cn + MCP）

# 第一章：系统概述与需求分析

## 1.1 系统定位与核心价值

本系统是一个面向医学领域的专业智能体协同平台，旨在通过多代理协作机制，为医疗机构、研究人员和普通用户提供全方位的医学AI服务。系统的核心价值主张体现在以下三个方面：

**智能化任务分解与协同**：系统能够自动分析用户输入的复杂医学问题，将其分解为多个子任务，并智能调度不同的专业代理协同完成，大幅提升问题解决的效率和质量。

**灵活的Skill生态集成**：支持skillhub.cn和MCP双协议，可无缝接入各类医学专业工具和知识库，构建开放的医学AI生态系统。

**人性化的交互体验**：支持语音输入、提示词优化、定时任务等功能，降低医学AI的使用门槛，让非技术用户也能轻松使用。

## 1.2 目标用户群体

| 用户群体 | 主要需求 | 使用场景 |
|---------|---------|---------|
| 临床医生 | 快速诊断辅助、病历分析、用药建议 | 门诊、查房、会诊 |
| 医学研究人员 | 文献检索、数据分析、论文写作 | 科研实验室、学术会议 |
| 医学生 | 学习辅导、病例练习、知识问答 | 课堂学习、临床实习 |
| 患者/公众 | 健康咨询、症状自查、就医指导 | 家庭健康、在线问诊 |
| 医院管理者 | 数据统计、质量监控、决策支持 | 医院运营管理 |

## 1.3 核心痛点与解决方案

当前医学AI应用存在以下主要痛点：

1. **功能单一，缺乏协同**：现有医学AI多为单一功能工具，无法处理复杂的综合性医学问题。本系统通过多代理协同架构，实现复杂任务的分解与协同处理。

2. **交互门槛高**：传统AI工具需要用户具备一定的技术能力。本系统支持语音输入、自然语言提示词，并提供一键优化功能，大幅降低使用门槛。

3. **数据孤岛**：医学知识分散在不同系统和知识库中。本系统通过Skill集成机制，打通各类医学数据源，构建统一的知识访问层。

4. **缺乏个性化**：通用AI难以满足医学专业需求。本系统设计了多个专业代理，针对不同医学领域提供专业化服务。

## 1.4 合规性要求

作为医学领域AI系统，必须满足以下合规要求：

- **数据安全**：符合《数据安全法》《个人信息保护法》要求，实现数据加密存储和传输
- **医疗合规**：遵循《互联网诊疗管理办法》《医疗质量管理办法》等法规
- **隐私保护**：符合HIPAA（国际）和等保2.0（国内）要求
- **算法透明**：提供AI决策的可解释性，满足医疗监管要求

## 1.5 系统差异化优势

| 维度 | 传统医学AI | 本系统 |
|-----|-----------|-------|
| 架构模式 | 单体应用 | 多代理协同 |
| 功能覆盖 | 单一功能 | 全场景覆盖 |
| 扩展性 | 封闭系统 | 开放Skill生态 |
| 交互方式 | 文本输入 | 语音+文本+提示词优化 |
| 任务处理 | 简单问答 | 复杂任务分解与协同 |
| 知识来源 | 固定知识库 | 动态Skill集成 |

# 第二章：系统架构设计

## 2.1 整体架构概览

本系统采用分层解耦的微服务架构，从下至上分为四个核心层次：基础设施层、数据层、服务层和应用层。各层之间通过标准化接口通信，确保系统的可扩展性和可维护性。

## 2.2 核心组件设计

### 2.2.1 代理编排中心（Agent Orchestrator）

代理编排中心是系统的核心大脑，负责：
- **任务解析**：接收用户输入，解析任务意图和约束条件
- **任务分解**：将复杂任务拆解为原子子任务
- **代理调度**：根据任务类型选择合适的专业代理
- **协同管理**：协调多代理之间的协作流程
- **结果整合**：汇总各代理输出，生成最终响应

### 2.2.2 专业代理集群（Professional Agents）

系统设计了8个专业代理，覆盖医学全场景：

| 代理名称 | 英文标识 | 核心职责 |
|---------|---------|---------|
| 编排代理 | OrchestratorAgent | 任务分解、代理调度、结果整合 |
| 诊断代理 | DiagnosisAgent | 临床诊断辅助、病历分析 |
| 研究代理 | ResearchAgent | 文献检索、数据分析、论文辅助 |
| 咨询代理 | ConsultationAgent | 健康咨询、症状自查、就医指导 |
| 知识代理 | KnowledgeAgent | 医学知识图谱查询、术语解释 |
| 工具代理 | ToolAgent | Skill调用、外部工具集成 |
| 质控代理 | QualityAgent | 结果审核、安全检查、合规验证 |
| 学习代理 | LearningAgent | 用户反馈学习、知识更新 |

### 2.2.3 Skill集成网关（Skill Gateway）

Skill集成网关提供统一的Skill接入能力：
- **协议适配**：支持skillhub.cn和MCP双协议
- **服务发现**：自动发现和注册可用Skill
- **负载均衡**：Skill调用的负载分发
- **熔断降级**：Skill故障时的优雅降级

### 2.2.4 大模型服务层（LLM Service with RAG）

对接大模型服务（192.168.0.214:8802/chat/），该服务已**内置RAG（检索增强生成）能力**，提供：
- **RAG检索增强**：内置医学知识向量库，自动检索相关医学知识增强生成效果
- **多模型支持**：支持不同规模和能力的医学大模型
- **Token计量**：精确计算输入输出Token数量
- **提示词管理**：提示词模板管理和优化
- **上下文管理**：长对话的上下文压缩和管理
- **知识溯源**：RAG检索结果可追溯，提供知识来源引用

**RAG架构说明：**
```
用户查询 → 大模型服务(192.168.0.214:8802/chat/)
              ↓
         ┌─────────────────────────────────────┐
         │         内置RAG引擎                  │
         │  ┌─────────┐    ┌─────────────┐    │
         │  │向量检索  │ →  │ 知识增强生成 │    │
         │  └─────────┘    └─────────────┘    │
         │  医学知识库: 疾病/药物/指南/文献    │
         └─────────────────────────────────────┘
              ↓
         增强后的响应（含知识引用）
```

**内置RAG知识库范围：**
| 知识类型 | 说明 |
|---------|-----|
| 疾病知识库 | ICD编码、疾病百科、诊断标准 |
| 药物知识库 | 药品信息、相互作用、用药指南 |
| 临床指南库 | 诊疗指南、专家共识、临床路径 |
| 医学文献库 | 论文摘要、研究数据 |
| 术语词典 | SNOMED CT、医学词典 |

## 2.4 数据流设计

系统数据流遵循以下路径：

1. **用户输入** → 语音/文本输入 → 输入预处理（ASR/文本清洗）
2. **任务解析** → 编排代理接收 → 意图识别 → 任务分解
3. **代理调度** → 选择专业代理 → 分发子任务
4. **并行处理** → 各代理并行/串行执行 → 调用Skill/LLM
5. **结果整合** → 汇总各代理输出 → 质控代理审核
6. **响应输出** → 格式化输出 → 返回用户

## 2.5 技术架构选型

| 层次 | 技术选型 | 说明 |
|-----|---------|-----|
| 应用层 | React/Vue + TypeScript | 响应式前端，支持多端适配 |
| API网关 | Kong/Nginx | 统一入口，限流熔断 |
| 服务层 | Python/FastAPI | 异步高性能，适合AI服务 |
| 消息队列 | RabbitMQ/Kafka | 异步任务处理，代理通信 |
| 数据库 | PostgreSQL + Redis | 结构化数据 + 缓存 |
| 大模型服务 | 内置RAG的医学大模型 | 192.168.0.214:8802/chat/，已集成向量检索和知识增强 |
| 容器化 | Docker + Kubernetes | 云原生部署，弹性伸缩 |
| 监控 | Prometheus + Grafana | 全链路监控告警 |

## 2.6 高可用与可扩展性设计

### 高可用设计
- **多活部署**：关键服务多实例部署，支持故障转移
- **数据备份**：数据库主从复制，定时备份
- **熔断降级**：服务异常时自动降级，保障核心功能

### 可扩展性设计
- **水平扩展**：无状态服务设计，支持按需扩容
- **插件化架构**：Skill热插拔，无需重启服务
- **代理动态注册**：新代理可动态加入集群

# 第三章：代理角色定义

## 3.1 代理角色总览

本系统设计了8个专业代理，形成完整的医学智能体协同网络。各代理既独立运作，又通过编排代理实现协同。

## 3.2 编排代理（OrchestratorAgent）

### 核心定位
系统的"大脑"，负责整体任务编排和代理协调。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| 任务解析 | 理解用户意图，提取关键信息 | 用户输入 | 任务意图对象 |
| 任务分解 | 将复杂任务拆解为子任务 | 任务意图 | 子任务列表 |
| 代理调度 | 选择合适代理执行子任务 | 子任务 | 调度计划 |
| 进度监控 | 跟踪任务执行状态 | 执行状态 | 进度报告 |
| 结果整合 | 汇总各代理输出 | 代理结果 | 最终响应 |
| 异常处理 | 处理执行失败和超时 | 异常信息 | 恢复策略 |

## 3.3 诊断代理（DiagnosisAgent）

### 核心定位
临床诊断辅助专家，提供病历分析和诊断建议。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| 病历分析 | 解析病历文本，提取关键信息 | 病历文本 | 结构化病历 |
| 症状识别 | 识别和标准化症状描述 | 症状文本 | 症状列表 |
| 诊断推理 | 基于症状进行诊断推理 | 症状+检验 | 诊断建议 |
| 鉴别诊断 | 提供鉴别诊断列表 | 初步诊断 | 鉴别诊断 |
| 用药建议 | 提供用药方案建议 | 诊断结果 | 用药方案 |
| 风险评估 | 评估患者风险等级 | 患者信息 | 风险报告 |

### 专业领域
- 内科疾病诊断
- 外科术前评估
- 妇产科诊断
- 儿科诊断
- 慢性病管理

## 3.4 研究代理（ResearchAgent）

### 核心定位
医学研究助手，支持文献检索、数据分析和论文写作。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| 文献检索 | 检索医学文献数据库 | 检索词 | 文献列表 |
| 文献摘要 | 生成文献摘要和要点 | 文献全文 | 摘要文本 |
| 数据分析 | 统计分析和可视化 | 研究数据 | 分析报告 |
| 论文辅助 | 论文结构建议和写作辅助 | 研究内容 | 论文草稿 |

### 支持的数据源
- PubMed/MEDLINE
- CNKI中国知网
- 万方数据
- Cochrane Library
- ClinicalTrials.gov

## 3.5 咨询代理（ConsultationAgent）

### 核心定位
健康咨询顾问，面向患者和公众提供健康指导。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| 健康咨询 | 回答健康相关问题 | 健康问题 | 咨询回复 |
| 症状自查 | 引导用户进行症状自查 | 症状描述 | 自查报告 |
| 就医指导 | 提供就医科室建议 | 症状/疾病 | 科室建议 |
| 用药指导 | 提供用药注意事项 | 药品名称 | 用药指导 |

## 3.6 知识代理（KnowledgeAgent）

### 核心定位
医学知识查询专家，通过大模型内置RAG服务提供医学知识检索和解释。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| 知识查询 | 通过RAG检索医学知识 | 查询词 | 知识结果（含来源引用） |
| 术语解释 | 解释医学术语含义 | 术语 | 解释文本 |
| 药物查询 | 查询药物信息和相互作用 | 药品名称 | 药物信息 |
| 疾病百科 | 提供疾病详细信息 | 疾病名称 | 疾病百科 |
| 指南检索 | 检索临床指南内容 | 关键词 | 指南内容 |

### 知识查询机制
知识代理通过调用大模型服务（192.168.0.214:8802/chat/）的内置RAG能力获取医学知识：

```
查询请求 → 大模型服务(内置RAG)
              ↓
         向量检索医学知识库
              ↓
         知识增强生成响应
              ↓
         返回结果 + 知识来源引用
```

### RAG内置知识库范围
| 知识类型 | 说明 |
|---------|-----|
| 疾病知识库 | ICD-10/ICD-11编码、疾病百科、诊断标准 |
| 药物知识库 | DrugBank药品信息、药物相互作用、用药指南 |
| 临床指南库 | 诊疗指南、专家共识、临床路径 |
| 医学文献库 | 论文摘要、研究数据 |
| 术语词典 | SNOMED CT医学术语、医学词典 |

## 3.7 工具代理（ToolAgent）

### 核心定位
工具集成专家，管理Skill和外部工具的调用。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| Skill发现 | 发现和注册可用Skill | Skill列表 | 注册状态 |
| Skill调用 | 执行Skill功能 | 调用参数 | 执行结果 |
| MCP适配 | 适配MCP协议工具 | MCP请求 | 工具响应 |
| 结果转换 | 转换工具输出格式 | 原始输出 | 标准格式 |

### 支持的Skill类型
| 类型 | 来源 | 示例 |
|-----|-----|-----|
| 诊断类 | SkillHub.cn | 症状分析、影像识别 |
| 检索类 | MCP | 文献检索、指南查询 |
| 计算类 | 本地 | 药物剂量计算、风险评分 |
| 可视化 | 本地 | 图表生成、报告导出 |

## 3.8 质控代理（QualityAgent）

### 核心定位
质量与安全守护者，确保输出质量和合规性。

### 主要职责
| 职责 | 描述 | 输入 | 输出 |
|-----|-----|-----|-----|
| 结果审核 | 审核代理输出质量 | 代理输出 | 审核报告 |
| 安全检查 | 检查敏感信息和风险 | 输出内容 | 安全报告 |
| 合规验证 | 验证输出符合医疗规范 | 输出内容 | 合规状态 |
| 偏见检测 | 检测输出中的偏见 | 输出内容 | 偏见报告 |

### 质量标准
- 医学准确性：≥95%
- 响应相关性：≥90%
- 安全合规率：100%
- 用户满意度：≥85%

## 3.9 学习代理（LearningAgent）

### 核心定位
系统进化引擎，持续学习和优化系统能力。

### 主要职责

| 反馈学习 | 从用户反馈中学习 | 反馈数据 | 学习结果 |

| 模型优化 | 优化代理模型参数 | 训练数据 | 优化报告 |
| 效果评估 | 评估系统整体效果 | 使用数据 | 评估报告 |

## 3.10 代理协作边界

各代理之间的协作遵循以下边界规则：

```
编排代理 → 可调度所有专业代理
```

## 4.1 任务分解算法

### 4.1.1 任务分解流程

### 4.1.2 任务类型定义

| 条件任务 | 根据条件分支执行 | 条件分解 | 根据诊断结果决定下一步 |
| 循环任务 | 重复执行直到满足条件 | 循环分解 | 多轮问诊收集症状 |

## 4.2 代理调度策略

### 4.2.1 调度算法设计

系统采用基于能力匹配和负载均衡的智能调度算法：

```
调度决策 = f(任务类型, 代理能力, 当前负载, 历史表现)
```

### 4.2.2 调度策略矩阵

| 调度场景 | 调度策略 | 说明 |
|---------|---------|-----|
| 单代理任务 | 能力最优匹配 | 选择能力最匹配的代理 |
| 多代理并行 | 负载均衡分配 | 根据当前负载分配任务 |
| 依赖任务 | 拓扑排序执行 | 按依赖关系顺序执行 |
| 紧急任务 | 优先级队列 | 高优先级任务优先处理 |
| 失败重试 | 备选代理切换 | 主代理失败时切换备选 |

## 4.3 协同工作流程

### 4.3.1 标准协同流程

1. 用户提交病例描述

```python
class MedicalTermProcessor:
    term_mapping = {
        "糖尿病": ["糖料病", "唐尿病"],
        "高血压": ["搞血压", "高血呀"],
        "心肌梗死": ["心机梗死", "心肌更死"],
        "脑卒中": ["脑足中", "脑中足"],
        "抗生素": ["抗生数", "抗升素"],
    }
    
    def correct_terms(self, text: str) -> str:
        for correct, wrong_list in self.term_mapping.items():
            for wrong in wrong_list:
                text = text.replace(wrong, correct)
        return text
```

```python
class TokenCalculator:
    def count_tokens(self, text: str) -> int:
        """计算文本Token数量"""
        # 中文约1.5字符/token，英文约4字符/token
        chinese_chars = sum(1 for c in text if '\u4e00' <= c <= '\u9fff')
        other_chars = len(text) - chinese_chars
        return int(chinese_chars / 1.5 + other_chars / 4)
    
    def estimate_cost(self, input_tokens: int, output_tokens: int, 
                      model: str) -> float:
        """估算成本"""
        pricing = {
            "medical-large": {"input": 0.01, "output": 0.02},
        }
        p = pricing.get(model, pricing["medical-large"])
        return (input_tokens * p["input"] + output_tokens * p["output"]) / 1000
```

## 8.5 代理实现框架

### 8.5.1 代理基类设计

```python
from abc import ABC, abstractmethod
from typing import Any, Dict, List, Optional
from dataclasses import dataclass
from enum import Enum

class AgentStatus(Enum):
    IDLE = "idle"
    BUSY = "busy"
    ERROR = "error"
    OFFLINE = "offline"

@dataclass
class AgentCapability:
    name: str
    description: str
    input_schema: dict
    output_schema: dict
    priority: int = 0

@dataclass
class TaskContext:
    task_id: str
    user_id: str
    conversation_id: str
    input: Any
    metadata: dict

@dataclass
class TaskResult:
    task_id: str
    success: bool
    output: Any
    error: Optional[str] = None
    metrics: dict = None

class BaseAgent(ABC):
    def __init__(self, config: dict):
        self.config = config
        self.status = AgentStatus.IDLE
        self.capabilities: List[AgentCapability] = []
        self.llm_client = None
        self.skill_gateway = None
        
    @abstractmethod
    async def initialize(self):
        pass
    
    @abstractmethod
    async def execute(self, context: TaskContext) -> TaskResult:
        pass
    
    @abstractmethod
    async def shutdown(self):
        pass
    
    def can_handle(self, task_type: str) -> bool:
        return any(cap.name == task_type for cap in self.capabilities)
    
    async def call_llm(self, messages: List[dict], **kwargs) -> dict:
        return await self.llm_client.chat(messages, **kwargs)
    
    async def invoke_skill(self, skill_id: str, input_data: dict) -> dict:
        return await self.skill_gateway.invoke(skill_id, input_data)
```

### 8.5.2 编排代理实现

```python
class OrchestratorAgent(BaseAgent):
    def __init__(self, config: dict):
        super().__init__(config)
        self.agents: Dict[str, BaseAgent] = {}
        
    async def initialize(self):
        self.capabilities = [
            AgentCapability(name="task_parsing", ...),
            AgentCapability(name="task_decomposition", ...),
            AgentCapability(name="agent_scheduling", ...),
        ]
        self.llm_client = LLMClient(self.config["llm"])
        self.skill_gateway = SkillGateway(self.config["skill_gateway"])
        
    async def execute(self, context: TaskContext) -> TaskResult:
        try:
            intent = await self._parse_intent(context.input)
            subtasks = await self._decompose_task(intent, context)
            schedule = await self._schedule_agents(subtasks)
            results = await self._execute_subtasks(schedule, context)
            final_result = await self._aggregate_results(results)
            return TaskResult(task_id=context.task_id, success=True, output=final_result)
        except Exception as e:
            return TaskResult(task_id=context.task_id, success=False, error=str(e))
```

## 10.5 AI安全与伦理

### 10.5.1 AI安全措施

| 安全风险 | 防护措施 |
|---------|---------|
| 对抗攻击 | 输入过滤、对抗训练 |
| 数据投毒 | 数据验证、异常检测 |
| 模型窃取 | API限流、输出过滤 |
| 隐私泄露 | 差分隐私、联邦学习 |
| 偏见歧视 | 公平性评估、去偏见 |

### 10.5.2 AI伦理准则

1. **透明性原则**: 明确告知用户正在与AI交互
2. **公平性原则**: 避免算法歧视和偏见
3. **安全性原则**: 确保AI系统安全可靠
4. **隐私保护原则**: 保护用户数据隐私
5. **人类监督原则**: 关键决策由人类最终确认

### 10.5.3 医疗AI特殊要求

- **辅助决策定位**: AI仅作为辅助工具，不替代医生诊断
- **责任界定**: 明确AI和医生的责任边界
- **风险告知**: 告知用户AI诊断的不确定性
- **持续监控**: 监控AI诊断准确率和偏差
- **紧急情况处理**: 识别紧急情况并提示就医
