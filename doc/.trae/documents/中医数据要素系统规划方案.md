# 中医数据要素系统规划方案

## 一、任务重述

### 1.1 目标
构建一个面向中医药行业的数据要素系统，实现中医药数据的标准化治理、资产化管理、安全流通和AI智能化应用，支撑"数智中医药"战略落地。

### 1.2 约束
- 符合国家数据局、国家中医药管理局政策要求
- 满足医疗数据安全合规（等保、密评、个人信息保护）
- 支持多源异构中医药数据接入
- 融入AI大模型等前沿技术

### 1.3 预期输出
- 系统功能模块清单与详细设计
- 技术架构方案
- AI应用场景与技术路线
- 分阶段开发周期估算
- 风险分析与应对建议

### 1.4 成功标准
- 数据治理覆盖率≥90%
- 数据质量评分≥85分
- AI辅助诊疗准确率≥85%
- 系统通过等保三级测评

---

## 二、任务分解

### 子任务1：数据治理基础能力建设
- **目的**：建立数据标准、分类分级、质量管控体系
- **输入**：国家中医药数据标准、医疗机构现有数据
- **输出**：数据治理中心（元数据、主数据、质量、血缘）
- **依赖**：无

### 子任务2：数据资产与流通平台建设
- **目的**：实现数据资产化管理和安全流通交易
- **输入**：治理后的高质量数据
- **输出**：数据资产目录、交易平台、隐私计算能力
- **依赖**：子任务1

### 子任务3：AI智能应用开发
- **目的**：将AI能力融入中医药诊疗、传承、管理等场景
- **输入**：治理数据、知识图谱、大模型
- **输出**：智能辅助开方、体质辨识、经验传承等应用
- **依赖**：子任务1、子任务2

### 子任务4：系统安全与合规保障
- **目的**：确保数据全生命周期安全合规
- **输入**：安全法规要求、系统架构
- **输出**：安全审计、合规报告、隐私保护机制
- **依赖**：贯穿全部子任务

## 四、系统核心功能模块

### P0级（基础必建）

#### 4.1 数据治理中心

**元数据管理**
- 技术元数据：数据库表结构、字段类型、存储位置、ETL作业信息
- 业务元数据：中医药业务术语定义、指标口径、数据字典（对接TCD中医病证分类与代码、ICD-11传统医学章节）
- 管理元数据：数据责任人、数据质量等级、数据敏感度标签
- 元数据自动采集：支持从关系型数据库、Hadoop、API等自动抓取元数据
- 元数据血缘分析：可视化展示数据从源到目标的完整流转路径

**主数据管理**
- 主数据建模：构建中医药领域核心主数据模型（患者主数据、医师主数据、药材主数据、方剂主数据、病证主数据）
- 主数据清洗与合并：基于规则+AI的重复数据识别与合并
- 主数据分发：向各业务系统同步标准主数据
- 主数据质量监控：完整性、一致性、准确性、时效性四维评估

**数据质量管理**
- 质量规则引擎：支持200+内置规则模板（空值检查、格式校验、范围校验、关联校验等）
- 自定义规则配置：可视化规则编排，支持SQL、Python脚本扩展
- 质量评分卡：按数据源、按主题域的多维度质量评分
- 质量问题闭环：问题发现 → 工单派发 → 整改跟踪 → 质量报告
- 质量报告自动化：日报/周报/月报自动生成与推送

**数据血缘追踪**
- 全链路血缘：从原始数据采集 → 清洗转换 → 数据仓库 → 数据服务 → 应用消费的全链路追踪
- 字段级血缘：精确到字段级别的血缘关系分析
- 影响分析：当上游数据变更时，自动分析对下游的影响范围
- 血缘可视化：交互式血缘图谱，支持正向追溯与反向溯源

#### 4.2 数据标准规范管理

**标准体系管理**
- 基础标准管理：数据元标准、编码标准、分类标准、术语标准
- 中医药专属标准库：
  - 《中医病证分类与代码》（TCD）全量收录与映射
  - ICD-11传统医学章节本土化映射
  - 《中药编码规则及编码》
  - 《中医临床诊疗术语》
  - 《中医药学名词》
- 标准版本管理：支持标准的新增、修订、废止全生命周期管理
- 标准对标分析：自动检测存量数据与标准的偏差

**数据模型规范**
- 主题域模型：临床诊疗、药材资源、名医经验、科研数据、健康管理五大主题域
- 逻辑模型设计工具：ER图可视化设计
- 模型评审流程：模型设计 → 评审 → 发布 → 变更的标准化流程
- 模型与物理库同步：DDL自动生成与版本对比

#### 4.3 数据分类分级管理

**分类体系**
- 按业务领域分类：临床医疗数据、药材生产数据、科研教育数据、行政管理数据、产业经济数据
- 按数据类型分类：结构化数据、半结构化数据、非结构化数据（医案文本、舌象图像、脉象波形等）

**分级体系（对接《医疗卫生行业数据分类分级指南》）**

| 级别 | 数据类型 | 示例 |
|------|----------|------|
| 核心数据（L4） | 国家核心中医药数据 | 珍稀濒危药材资源分布、国家战略储备药材信息 |
| 重要数据（L3） | 重要业务数据 | 名老中医核心秘方、国家重点课题原始数据 |
| 敏感数据（L2） | 个人信息与隐私数据 | 患者诊疗记录、体质辨识结果、个人健康档案 |
| 一般数据（L1） | 公开或内部数据 | 中药材市场价格、公开医案（脱敏后）、科普知识 |

**分级管控策略**
- 自动分级识别：基于内容识别+规则引擎自动标注数据级别
- 分级访问控制：不同级别数据匹配不同的访问审批流程和技术防护措施
- 分级存储策略：核心数据加密存储+异地灾备，一般数据常规存储
- 分级流通管控：数据对外共享/交易时的级别校验与脱敏策略自动匹配

#### 4.4 数据资产管理

**资产目录**
- 资产自动盘点：基于元数据自动识别和登记数据资产
- 资产编目：按主题域、业务线、数据域多维组织资产目录
- 资产标签体系：业务标签、技术标签、管理标签、价值标签
- 资产检索：支持自然语言检索的智能搜索引擎

**资产估值与定价**
- 成本法估值：数据采集成本、存储成本、治理成本核算
- 收益法估值：基于数据应用场景的预期收益评估
- 市场法参考：同类数据产品市场交易价格参考
- 定价模型：基础定价 + 质量系数 + 稀缺系数 + 时效系数

**资产入表支撑**
- 资产确权登记：数据资源持有权、加工使用权、产品经营权三权分置登记
- 成本归集：满足《企业数据资源相关会计处理暂行规定》的成本归集要求
- 资产报表：自动生成数据资产台账、变动表、减值测试报告
- 审计追踪：完整的资产形成过程审计日志

### P1级（重要支撑）

#### 4.5 用户与权限管理

**组织架构管理**
- 多级租户体系：支持省-市-县-机构四级组织架构
- 机构类型：中医院、综合医院中医科、中医诊所、科研院所、药企、监管机构
- 机构资质管理：执业许可证、等级评审信息的数字化管理

**用户身份管理**
- 统一身份认证：支持CA证书、国密SM2、OAuth2.0、LDAP
- 多因素认证：密码+短信/指纹/人脸
- 用户画像：基于角色的用户能力画像

**权限管控**
- RBAC+ABAC混合模型：基于角色+属性的细粒度权限控制
- 数据级权限：行级、列级数据访问控制
- 功能级权限：菜单、按钮、API级别控制
- 动态授权：基于数据分类分级的动态权限调整

#### 4.6 数据采集与接入管理

**多源接入适配**
- 数据库接入：MySQL、Oracle、PostgreSQL、SQL Server、达梦、人大金仓
- 大数据平台接入：Hadoop、Hive、ClickHouse、StarRocks
- 消息队列接入：Kafka、RabbitMQ、RocketMQ
- API接入：RESTful API、WebService、GraphQL
- 文件接入：Excel、CSV、XML、JSON、PDF、图片、音视频

**中医药特色数据源**
- 医院信息系统（HIS）：门诊/住院电子病历
- 中医电子病历系统（EMR）：四诊信息、辨证论治记录
- 实验室信息系统（LIS）：检验检查结果
- 影像系统（PACS）：舌象、面象等中医特色影像
- 中医体质辨识系统：体质问卷与辨识结果
- 名老中医传承工作室：跟师笔记、医案、音视频
- 中药溯源系统：种植、采收、加工、流通全链条数据

**数据接入治理**
- 接入申请审批：数据源注册 → 合规审查 → 技术对接 → 上线运行
- 接入监控：实时接入量、成功率、延迟监控
- 接入质量校验：接入数据的首检与持续监控

#### 4.7 数据目录与检索服务

**数据目录**
- 资产目录视图：分层分域的数据资产全景图
- 数据详情页：数据定义、样例数据、质量评分、使用说明、申请入口
- 数据热度排行：浏览量、申请量、调用量综合排序
- 数据推荐：基于用户角色的智能推荐

**智能检索**
- 全文检索：支持数据表、字段、指标、文档的全文搜索
- 语义检索：基于中医药知识图谱的语义理解搜索
- 以数搜数：上传数据样例，自动匹配相似数据集
- 检索结果智能排序：综合相关性、质量、热度排序

### P2级（价值提升）

#### 4.8 数据交易与流通管理

**交易前**
- 数据产品封装：将原始数据加工为标准数据产品（数据集、API、报告、模型）
- 产品发布审核：合规性、安全性、定价审核
- 需求发布：数据需求方发布采购需求，智能匹配供给方

**交易中**
- 在线签约：电子合同签署，明确数据使用范围、期限、方式
- 安全交付：隐私计算环境下的数据可用不可见交付
- 计费结算：按次/按量/包月/包年多种计费模式
- 交易存证：区块链存证，确保交易可追溯、不可篡改

**交易后**
- 使用监控：数据使用行为的实时监控与审计
- 效果评估：数据应用效果反馈与价值评估
- 争议处理：交易纠纷的在线调解与仲裁支撑

**隐私计算支撑**
- 多方安全计算（MPC）：联合统计分析场景
- 联邦学习：跨机构AI模型训练场景
- 可信执行环境（TEE）：敏感数据处理场景
- 数据脱敏与匿名化：K-匿名、差分隐私等技术

#### 4.9 统计分析与大屏

**运营统计**
- 数据资源统计：数据量、数据源数、数据类型分布
- 数据质量统计：质量评分趋势、问题分布、整改率
- 数据流通统计：交易量、交易额、活跃用户数
- 系统运行统计：API调用量、响应时间、可用性

**主题分析**
- 中医药服务分析：诊疗人次、病种分布、疗效分析
- 药材产业分析：种植面积、产量、价格趋势、流通分析
- 名医传承分析：传承谱系、医案统计、学术影响力
- 科研数据分析：课题分布、成果转化、论文产出

**可视化大屏**
- 领导驾驶舱：一屏总览中医药数据要素全景
- 业务专题屏：按主题域的深入分析大屏
- 移动端适配：支持手机、平板访问

#### 4.10 AI智能应用中心

**智能辅助开方**
- 症状采集：结构化四诊信息采集（症状、舌象、脉象、体征）
- 辨证推理：基于知识图谱+大模型的智能辨证
- 方剂推荐：根据证型推荐经典方剂及加减化裁建议
- 用药禁忌提醒：十八反十九畏、妊娠禁忌、药物相互作用
- 处方审核：AI辅助合理性审核

**中医体质辨识**
- 智能问卷：基于《中医体质分类与判定》标准的智能问卷
- 多模态辨识：结合舌象图像识别、面象分析的辅助辨识
- 体质报告：个性化体质分析报告与调养建议
- 体质追踪：历次辨识结果的对比分析与趋势预测

**名老中医经验传承**
- 医案结构化：NLP自动提取医案中的症状、辨证、治法、方药
- 经验挖掘：关联规则挖掘、聚类分析发现诊疗规律
- 传承谱系：可视化师承关系与学术流派谱系
- 数字分身：基于名医历史医案训练的个性化诊疗助手

**中药饮片追溯**
- 全链条追溯：种植 → 采收 → 加工 → 检验 → 流通 → 使用
- 质量预警：基于检验数据的异常预警
- 溯源查询：扫码/批次号查询完整溯源信息

**智能知识服务**
- 中医药知识图谱：涵盖疾病、证型、症状、方剂、中药、经络、穴位等实体及关系
- 智能问答：基于大模型的中医药知识问答
- 文献智能检索：跨库文献的智能检索与摘要生成

### P3级（安全保障与运营）

#### 4.11 数据安全与合规审计

**安全管控**
- 数据加密：传输加密（TLS1.3）、存储加密（AES-256/SM4）
- 密钥管理：HSM硬件密钥管理，支持国密算法
- 脱敏引擎：静态脱敏、动态脱敏、格式保留脱敏
- 水印溯源：数字水印嵌入，泄露溯源
- 访问控制：零信任架构，最小权限原则

**合规审计**
- 等保合规：等级保护2.0三级/四级要求落地
- 密评合规：商用密码应用安全性评估
- 个人信息保护：符合《个人信息保护法》要求
- 审计日志：全量操作日志，支持行为追溯
- 合规报告：自动生成合规自检报告

#### 4.12 数据运营与增值服务

**运营支撑**
- 数据需求管理：需求收集、评估、排期、交付全流程
- 数据服务管理：API服务的注册、发布、监控、下线
- 用户运营：用户活跃度分析、满意度调查、培训支撑

**增值服务**
- 数据报告服务：定制化行业分析报告
- 数据咨询服务：数据治理咨询、数字化转型咨询
- 数据培训服务：数据素养培训、工具使用培训

### 6.2 中医知识图谱

**图谱 Schema 设计**

```
实体类型：
- 疾病（中医病名、西医病名）
- 证型（八纲辨证、脏腑辨证、气血津液辨证等）
- 症状（主症、兼症、舌象、脉象）
- 方剂（经方、时方、验方）
- 中药（单味药、药对、药组）
- 穴位（十四经穴、经外奇穴）
- 经络（十二正经、奇经八脉）
- 治法（汗吐下和温清消补等）
- 体质（平和质、气虚质、阳虚质等九种体质）
- 名医（姓名、流派、擅长领域）

关系类型：
- 疾病 → 常见证型 → 证型
- 证型 → 典型症状 → 症状
- 证型 → 推荐治法 → 治法
- 治法 → 代表方剂 → 方剂
- 方剂 → 组成药物 → 中药
- 中药 → 性味归经 → 经络
- 症状 → 对应穴位 → 穴位
- 名医 → 擅长治疗 → 疾病
- 名医 → 学术传承 → 名医
```

**构建流程**
1. **知识抽取**：从古籍、医案、文献中抽取实体和关系（BERT+CRF、UIE等）
2. **知识融合**：实体对齐、关系去重、冲突消解
3. **知识推理**：基于规则+图神经网络的知识补全
4. **知识存储**：Neo4j图数据库存储 + Elasticsearch索引
5. **知识更新**：持续从新的医案和文献中增量更新

| 风险描述 | 风险等级 | 应对措施 |
|----------|----------|----------|
| 中医药数据来源分散、格式各异、质量参差不齐 | 高 | 建立严格的数据接入审核机制；投入足够的数据清洗资源；设计灵活的数据映射适配层 |
| 中医术语标准化程度低，同一概念多种表述 | 高 | 构建中医药术语标准库；引入NLP语义对齐技术；建立术语映射关系库 |
| 名老中医经验数据多为非结构化文本，难以数字化 | 高 | 采用NLP+人工标注结合的方式；设计医案结构化模板；引入OCR+语音识别技术 |
| 数据更新不及时，导致知识陈旧 | 中 | 建立数据更新机制；设置数据时效性监控；定期知识库刷新 |

### 8.3 技术与算法风险

| 风险描述 | 风险等级 | 应对措施 |
|----------|----------|----------|
| AI辅助诊疗的准确性和安全性要求极高，误诊风险 | 高 | 明确AI定位为"辅助"而非"替代"；建立人机协同审核机制；设置高风险场景人工强制复核 |
| 大模型幻觉问题，生成不准确的中医药知识 | 高 | RAG检索增强降低幻觉；知识图谱约束生成内容；建立模型输出审核机制 |
| 多模态数据（舌象、脉象）采集标准化困难 | 中 | 制定采集设备标准规范；设计质量控制算法；建立标准数据集 |
| 系统性能与扩展性挑战 | 中 | 采用云原生架构；设计水平扩展能力；建立性能基准测试体系 |

### 8.4 业务与运营风险

| 风险描述 | 风险等级 | 应对措施 |
|----------|----------|----------|
| 医疗机构数据共享意愿低，数据孤岛难以打破 | 高 | 设计合理的利益分配机制；提供数据安全可信保障；从政策推动的试点机构切入 |
| 名老中医对数字化传承的接受度不确定 | 中 | 尊重传统、保护知识产权；设计便捷的数字化工具；让名医参与产品设计 |
| 数据产品市场需求不明确，交易活跃度不足 | 中 | 前期以内部应用为主，验证价值；逐步开放外部交易；提供多样化的数据产品形态 |
| 用户（医师）使用习惯改变困难 | 中 | 设计符合中医思维的操作流程；提供充分的培训支持；保持系统的易用性 |

### 8.5 安全与隐私风险

| 风险描述 | 风险等级 | 应对措施 |
|----------|----------|----------|

| 系统遭受网络攻击 | 中 | 等保三级/四级建设；渗透测试；应急响应预案；灾备演练 |

## 九、总结与建议

### 9.1 核心成功要素

1. **标准先行**：数据标准是系统建设的根基，应优先投入资源建立完善的中医药数据标准体系，并持续与国家最新标准保持同步。

2. **安全合规贯穿始终**：数据分类分级、隐私保护、等保合规不是后期补丁，而是需要从架构设计之初就融入系统的核心能力。

3. **AI与业务深度融合**：AI不是独立模块，而是嵌入到数据治理、临床辅助、经验传承等业务流程中的增强能力，需要与业务专家紧密协作。

4. **生态共建**：中医数据要素系统的价值在于连接医疗机构、科研院所、药企、监管部门等多方主体，需要设计合理的利益共享机制。

5. **渐进式演进**：建议采用"小步快跑、持续迭代"的方式，从数据治理基础能力起步，逐步叠加数据流通、AI应用等高级能力。

### 9.2 预期成效

- **治理层面**：实现中医药数据的全生命周期规范化管理，数据质量显著提升
- **业务层面**：支撑智能辅助诊疗、体质辨识等场景，提升基层中医药服务能力
- **传承层面**：名老中医经验得到有效数字化保存和智能化传承
- **产业层面**：激活中医药数据要素价值，促进数据驱动的产业创新
- **监管层面**：为中医药行业监管提供数据支撑和决策依据

### 9.3 总体开发周期

- **完整系统交付**：16-22个月（三阶段串行）
- **核心功能交付（敏捷并行）**：12-14个月
- **团队峰值规模**：21人（第三阶段）
- **持续运营团队**：10人

> 本方案基于《关于促进数字中医药发展的若干意见》政策要求，结合数据要素流通交易的最佳实践，以及AI大模型在中医药领域的最新技术进展进行设计。方案可根据实际资源投入、业务优先级和政策要求进行灵活调整。
