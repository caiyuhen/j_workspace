# CDISC SDTM Implementation Guide v3.4 完整中文版 (续)

## 第 3 章 以标准格式提交数据

## 3.1 数据集内容和属性的标准元数据

所有提交的数据集必须包含完整的元数据，以确保数据可理解、可验证和可重用。元数据包括:

### 必需元数据元素

**数据集级元数据**:
- 数据集名称
- 数据集标签
- 数据集描述
- 创建/更新日期
- 数据来源

**变量级元数据**:
- 变量名称
- 变量标签
- 变量类型 (字符型/数值型)
- 变量长度
- 变量描述
- 允许值或受控术语引用

### 元数据标准

CDISC 定义了标准元数据格式:
- SDTM Define XML
- Define 2.0/2.1格式
- 提交数据集元数据 (SDTM Metadata)

## 3.2 在监管提交中使用 CDISC 域模型 – 数据集元数据

### 3.2.1 数据集级元数据

数据集级元数据提供数据集的整体信息:

**关键属性**:
- **Study Name**: 研究名称
- **Study ID**: 研究标识符
- **Dataset Name**: 数据集名称
- **Dataset Label**: 数据集标签
- **Observational Class**: 观察类别
- **Origin**: 数据来源

**示例元数据**:
```xml
<dataset name="AE" orig="CRF">
  <attr name="USUBJID" type="text" length="8"/>
  <attr name="AETERM" type="text" length="200"/>
  <!-- 更多变量定义 -->
</dataset>
```

### 3.2.1.1 主键

主键用于唯一标识数据集中的每条记录。

**标准主键结构**:
- STUDYID (研究标识符)
- USUBJID (受试者唯一标识符)
- 域特定标识符 (如 ASEQ, LBSEQ)

**主键要求**:
1. 每个数据集必须有主键
2. 主键值在该数据集内必须唯一
3. 主键不应包含缺失值

**示例**:
- AE 域：STUDYID + USUBJID + AESEQ
- LB 域：STUDYID + USUBJID + LBSEQ + LBSPEC (如适用)

### 3.2.1.2 CDISC 提交值级元数据

值级元数据描述变量值的含义和约束:

**受控术语引用**:
- 值列表名称 (Codelist Name)
- 值列表版本
- 编码系统 (如 MedDRA, WHO Drug)

**格式说明**:
- 日期格式 (如 YYYY-MM-DD)
- 数值范围 (如 0-100)
- 模式 (Pattern)

**示例**:
```
变量：AESEV
标签：不良事件严重程度
类型：字符型
长度：8
允许值：MILD, MODERATE, SEVERE
受控术语：CDISC Controlled Terminology
```

### 3.2.2 符合性

提交的数据必须符合以下要求:

**SDTM 标准符合性**:
- 使用正确版本的 SDTM 标准
- 遵循实施指南中的规则
- 使用最新的受控术语

**数据质量要求**:
- 数据完整性
- 数据一致性
- 数据准确性
- 时间逻辑正确性

**监管要求**:
- FDA 21 CFR Part 11
- PMDA 数据提交指南
- 其他监管机构要求

**验证工具**:
- CDISC 标准验证器
- SDTM 数据质量评估工具
- 自定义验证规则

## 第 4 章 域模型假设

本章定义了 SDTM 域模型的一般假设和规则。

### 4.1 通用域假设

#### 4.1.1 查阅 SDTM 和实施指南

在编制数据前，应:
1. 仔细阅读 SDTM 标准文档
2. 查阅最新的实施指南
3. 理解相关域的要求
4. 参考示例数据

#### 4.1.2 与分析数据集的关系

SDTM 数据集是汇总数据，不是分析数据集:
- SDTM 保留原始数据的颗粒度
- 分析数据集 (ADaM) 基于 SDTM 创建
- SDTM 不应包含分析变量

#### 4.1.3 额外时间变量

除了标准时间变量外，可能需要:
- 额外的日期/时间变量
- 持续期变量
- 相对时间变量

**时间变量命名**:
- 开始日期：--STDTC
- 结束日期：--ENDTDC
- 持续时间：--DUR

#### 4.1.3.1 EPOCH 变量指导

EPOCH 变量用于标识试验阶段:
- SCREENING (筛选期)
- DOSING (给药期)
- FOLLOWUP (随访期)
- POSTTREATMENT (治疗后)

**EPOCH 使用示例**:
```
USUBJID    VISIT      AETERM        AEPOCH
1001-001   DAY 1      HEADACHE      DOSING
1001-001   DAY 30     NAUSEA        FOLLOWUP
```

#### 4.1.4 变量顺序

变量在数据集中应按以下顺序排列:
1. 标识变量 (STUDYID, USUBJID 等)
2. 域特定标识符 (--SEQ, --GRPID)
3. 时间变量
4. 主题变量
5. 结果变量
6. 修饰变量
7. 补充变量

#### 4.1.5 SDTM 核心指定

变量具有以下核心状态:

| 核心状态 | 说明 |
|----------|------|
| Required | 必须包含 |
| Conditional | 条件性包含 |
| Contextual | 上下文相关 |
| Tabular Data | 表格数据 |

**Required 变量示例**:
- STUDYID
- USUBJID
- --SEQ
- 域特定必需变量

#### 4.1.6 数据集命名指导

数据集命名规则:
- 使用两字母大写字母标识符
- 避免使用保留字
- 保持命名一致性

**标准数据集**:
- AE (不良事件)
- DM (人口统计学)
- LB (实验室检测)

**补充数据集**:
- SUPPAA (AE 的补充 qualifiers)
- SUPPAB (其他补充)

#### 4.1.7 拆分域

在某些情况下，可能需要将一个域拆分为多个数据集:

**拆分原因**:
- 数据量过大
- 数据结构差异
- 访问模式不同

**拆分原则**:
- 保持数据完整性
- 使用--GRPID 关联
- 在元数据中说明拆分原因

#### 4.1.7.1 问卷拆分示例

对于大型问卷，可以按部分拆分:

```
原问卷：QS (全部问题)
拆分后:
- QSPART1 (第 1 部分)
- QSPART2 (第 2 部分)
使用 QSGRPID 关联
```

#### 4.1.8 来源元数据

来源 (Origin) 元数据标识数据的来源:

**标准来源值**:
- CRF (病例报告表)
- CALC (计算得出)
- DERIVED (派生)
- ISSUER (发布者)
- SOURCE (原始数据)

**来源记录示例**:
```
ORRESORIG = CRF  (来自 CRF)
ORRESORIG = CALC (计算得出)
```

#### 4.1.8.1 变量来源元数据

为每个变量定义来源:
- ORVARORIG (变量来源)
- 说明变量是如何创建的

#### 4.1.8.2 记录来源元数据

为每条记录定义来源:
- ORRESORIG (结果来源)
- 说明记录的数据来源

#### 4.1.9 在元数据中分配自然键

自然键 (Natural Key) 是业务层面的唯一标识符:

**自然键示例**:
- 实验室检测：测试名称 + 样本日期
- 不良事件：事件术语 + 开始日期

**自然键用途**:
- 数据验证
- 记录匹配
- 数据审查

### 4.2 通用变量假设

#### 4.2.1 变量命名约定

SDTM 变量命名规则:
- 全部大写
- 使用下划线分隔片段
- 最大长度 8 个字符 (对于--XX 格式)
- 使用标准命名片段

**命名片段示例**:
- STD (开始)
- END (结束)
- DUR (持续期)
- FL (标志)
- CAT (类别)

**变量命名示例**:
- AESTDTC (不良事件开始日期时间)
- AESDTC (不良事件开始日期)
- AEENDTC (不良事件结束日期时间)

#### 4.2.2 两字符域标识符

每个域使用两字母标识符:
- 全部大写
- 有明确的业务含义
- 在 SDTM 标准中定义

**示例**:
- AE = Adverse Events
- DM = Demographics
- LB = Laboratory Tests

#### 4.2.3 "受试者"和 USUBJID 的使用

USUBJID 是受试者在研究中的唯一标识符:
- 格式：STUDYID + 受试者号
- 示例：STUDY001-1001
- 在所有数据集中保持一致

#### 4.2.4 提交数据中的文本大小写

文本值的大小写规则:
- 受控术语：使用定义的大小写
- 自由文本：保持原始大小写或统一大写
- 日期时间：使用标准格式

**受控术语示例**:
- AESEV: MILD, MODERATE, SEVERE (大写)
- AEREL: YES, NO, UNKNOWN (大写)

#### 4.2.5 缺失值约定

缺失值的表示:
- 字符型变量：空白字符串
- 数值型变量：点号 (.)
- 日期时间：空白字符串

**缺失值类型**:
- 未收集 (Not Collected)
- 不适用 (Not Applicable)
- 未知 (Unknown)
- 未回答 (Not Asked)

#### 4.2.6 分组变量和分类

分组变量用于对观测进行分类:

**分组变量示例**:
- AECAT (不良事件类别)
- LBCAT (实验室类别)
- VSCAT (生命体征类别)

**分类层级**:
- 一级分类
- 二级分类
- 三级分类

#### 4.2.7 提交 CRF 中的自由文本

自由文本的处理:
- 保留原始文本
- 使用 SUPP-- 数据集存储额外信息
- 在--SP 变量中说明

**自由文本变量**:
- --SPEC (说明)
- --SCAT (说明类别)

#### 4.2.7.1 非结果修饰变量的"指定"值

对于非结果修饰变量，使用:
- --SP 变量存储指定值
- --SCAT 变量分类指定类型

#### 4.2.7.2 结果修饰变量的"指定"值

对于结果修饰变量:
- 使用 SUPP-- 数据集
- 定义清晰的变量标签

#### 4.2.7.3 主题变量的"指定"值

主题变量的指定:
- 在主题变量后加 SPEC
- 示例：AESPEC, LBTESTSP

#### 4.2.7.4 --OBJ 的"指定"值

对象变量的指定:
- --OBJSP 变量
- 在 SUPP-- 中详细说明

#### 4.2.8 变量的多个值

当一个变量有多个值时:

**处理方法**:
- 使用多条记录
- 使用 SUPP-- 数据集
- 使用分隔符 (不推荐)

#### 4.2.8.1 干预或事件主题变量的多个值

干预/事件主题的多个值:
- 创建多条记录
- 使用--GRPID 分组

#### 4.2.8.2 发现结果变量的多个值

发现结果的多个值:
- 按参数拆分记录
- 使用--PARCAT 分类

#### 4.2.8.3 非结果修饰变量的多个值

使用 SUPP-- 数据集:
```
USUBJID  AESEQ  QNAM        QVAL
1001-001 1      AEANATOM    HEAD
1001-001 1      AESUBANAT   FRONTAL
```

#### 4.2.8.4 参数的多个值

参数的多个值:
- 使用--PAR 变量
- 创建多条记录

#### 4.2.9 变量长度

变量长度标准:
- 标识变量：根据需求定义
- 文本变量：通常 200 字符
- 日期时间：固定格式长度

**常见长度**:
- STUDYID: 20
- USUBJID: 8
- 自由文本：200
- 日期：10 (YYYY-MM-DD)

### 4.3 编码和受控术语假设

#### 4.3.1 受控术语、值列表或格式列

受控术语的使用:
- 引用 CDISC 受控术语
- 使用标准值列表
- 定义格式规则

**受控术语来源**:
- CDISC Controlled Terminology
- MedDRA
- WHO Drug
- 自定义值列表

#### 4.3.2 受控术语文本大小写

受控术语的大小写:
- 使用定义的大小写
- 保持一致性
- 在元数据中说明

#### 4.3.3 受控术语值

受控术语值:
- 使用标准编码
- 保持值稳定性
- 记录版本信息

#### 4.3.4 受控术语和任意数字代码的使用

数字代码的使用:
- 与文本值一起使用
- 在元数据中定义
- 避免歧义

#### 4.3.5 同义词修饰变量的受控术语存储

同义词的存储:
- 主术语使用受控术语
- 同义词在 SUPP-- 中存储

#### 4.3.6 通用域模型的主题变量存储

主题变量存储:
- 使用标准变量名
- 引用受控术语
- 提供说明变量

#### 4.3.7 "是"和"否"值的使用

YES/NO值的使用:
- 使用标准值：YES, NO, UNKNOWN
- 保持一致性
- 在元数据中定义

### 4.4 实际和相对时间假设

#### 4.4.1 日期/时间变量的格式

日期时间格式标准:
- 日期：YYYY-MM-DD
- 日期时间：YYYY-MM-DDTHH:MM:SS
- 时间：HH:MM:SS

**示例**:
- 2023-01-15
- 2023-01-15T14:30:00
- 14:30:00

#### 4.4.2 日期/时间精度

日期时间精度:
- 根据数据收集精度定义
- 保持一致性
- 在元数据中说明

**精度级别**:
- 年：YYYY
- 年月：YYYY-MM
- 日期：YYYY-MM-DD
- 日期时间：YYYY-MM-DDTHH:MM:SS

#### 4.4.3 --DUR 变量的持续期和时间间隔使用

持续期变量:
- 使用--DUR 后缀
- 单位在标签中说明
- 数值型变量

**示例**:
- AEDUR (不良事件持续期，单位：天)
- VSDUR (测量持续期，单位：分钟)

#### 4.4.3.1 时间间隔和持续期使用

时间间隔计算:
- 结束日期 - 开始日期
- 考虑时区
- 处理缺失值

#### 4.4.3.2 不确定间隔

不确定间隔的处理:
- 使用范围值
- 在 SUPP-- 中说明
- 使用特殊标志

#### 4.4.4 研究日变量的使用

研究日计算:
- 研究日 1 = 首次给药日
- 使用--SDY 变量
- 整数类型

**示例**:
```
STUDYID  USUBJID  VISITDT   SDY
STUDY1   001      2023-01-10  1
STUDY1   001      2023-01-17  8
```

#### 4.4.5 临床接触和访视

临床接触和访视的关系:
- 访视：计划的评估时间点
- 临床接触：实际的医疗接触
- 使用 SV 域记录

#### 4.4.6 表示额外研究日

额外研究日:
- 使用相对日
- 负数表示给药前
- 在标签中说明参考点

#### 4.4.7 相对时间变量的使用

相对时间变量:
- 相对于参考时间点
- 使用--REL 后缀
- 在标签中说明参考点

#### 4.4.8 基于发现的域中报告的日期和时间

发现域的日期时间:
- 测量日期时间
- 样本采集日期时间
- 结果报告日期时间

#### 4.4.9 作为结果变量的日期使用

日期作为结果:
- 使用标准日期格式
- 在标签中说明含义
- 考虑时区

#### 4.4.10 表示时间点

时间点表示:
- 使用标准时间格式
- 包括时区信息
- 在元数据中说明

#### 4.4.11 疾病里程碑和疾病里程碑时间变量

疾病里程碑:
- 使用 SM 域
- 定义里程碑类型
- 记录日期

### 4.5 其他假设

#### 4.5.1 发现的原始和标准化结果以及未执行的测试

**原始结果**:
- 实验室报告的原始值
- 原始单位

**标准化结果**:
- 转换为标准单位
- 标准化术语

**未执行的测试**:
- 使用"N"或"TEST NOT DONE"
- 在--ORRESU 中记录原始单位

#### 4.5.1.1 原始和标准化结果

原始和标准化结果的存储:
- --ORRES: 原始结果
- --STRES: 标准化结果
- --ORRESU: 原始单位
- --STRESU: 标准化单位

#### 4.5.1.2 未执行的测试

未执行测试的标记:
- 结果变量：N 或 TEST NOT DONE
- 在元数据中说明

#### 4.5.1.3 原始和标准单位及未执行测试示例

```
USUBJID  LBTEST   LBORRES  LBORRESU  LBSTRES  LBSTRESU
1001-001 CHOLESTEROL 200   MG/DL     5.2      MMOL/L
1001-001 GLUCOSE    N      TEST NOT DONE
```

#### 4.5.2 链接多个观测

链接多个观测:
- 使用--GRPID
- 使用 RELREC 数据集
- 在元数据中说明关系

#### 4.5.3 超过通用观察类别域变量最大长度的文本字符串

长文本处理:
- 使用 SUPP-- 数据集
- 截断并添加标志
- 在元数据中说明

#### 4.5.3.1 测试名称 (--TEST) 超过 40 个字符

测试名称过长:
- 截断到 40 字符
- 使用 SUPP-- 存储完整名称

#### 4.5.3.2 其他变量中超过 200 个字符的文本字符串

长文本:
- 截断到 200 字符
- 使用 SUPP-- 存储完整内容

#### 4.5.4 干预和事件观察类别中的评估者

评估者信息:
- 使用--评估者变量
- 记录评估者类型
- 在元数据中说明

#### 4.5.5 发现观察类别数据的临床意义

临床意义:
- 使用--FN 变量 (发现标志)
- 使用受控术语
- 提供阈值信息

#### 4.5.6 补充原因变量

补充原因:
- 使用 SUPP-- 数据集
- 定义清晰的 QNAM
- 在元数据中说明

#### 4.5.7 预设干预和事件的存在或缺失

存在/缺失:
- 使用标志变量
- 使用受控术语：PRESENT, ABSENT
- 在元数据中定义

#### 4.5.8 长期随访的考虑

长期随访:
- 使用随访标志
- 记录随访日期
- 在元数据中说明随访计划

#### 4.5.9 基线值

基线值:
- 使用基线标志
- 定义基线时间窗
- 在元数据中说明
