## 1. 产品背景与目标

### 1.1 问题陈述

当前慢病/亚健康人群数量庞大，但健康管理呈碎片化状态：体检数据孤岛、随访不连续、干预方案缺乏个性化、医患沟通低效。企业员工健康福利普遍缺乏系统化管理工具。

### 1.2 产品目标

| 目标维度 | 具体目标 |
|---------|---------|
| 用户价值 | 患者获得全流程、个性化、AI 辅助的健康管理服务 |
| 业务价值 | 为企业主提供员工健康管理 SaaS 服务，提升健管师工作效率 ≥ 40% |
| 系统目标 | 覆盖从健康档案建立 → 监测 → 预警 → 干预 → 复盘的全生命周期 |
| AI 目标 | 80% 常规问询由 AI Agent 自动处理，医生/健管师聚焦高价值决策 |

### 1.3 成功指标（KPI）

- 患者月活率 ≥ 60%（健康任务完成率驱动）
- AI 问答满意度 ≥ 85%（5 分制打分）
- 健管师人均服务患者数从 50 人/月 → 120 人/月
- 高风险患者 30 天内触达率 ≥ 95%
- 企业客户年续约率 ≥ 85%

## 2. 用户与市场分析

### 2.1 目标用户群

| 角色 | 核心诉求 | 痛点 |
|------|---------|------|
| 患者 | 了解自己健康状态，获得专属建议 | 报告看不懂，缺乏持续指导 |
| 企业主 | 管理员工健康，控制医疗成本 | 数据分散，无法量化健康收益 |
| 健康管理师 | 高效管理多位患者，及时干预 | 手工记录多，重复工作量大 |
| 医生 | 快速了解患者全貌，精准诊疗 | 历史数据碎片化，沟通效率低 |
| 客服 | 快速响应用户诉求 | 咨询量大，标准化程度低 |
| 超级管理员 | 平台运营、权限管理、合规审计 | 缺乏统一管控视图 |

### 2.2 核心用户故事

- **作为患者**，我希望通过手机随时查看自己的健康数据和 AI 给出的建议，以便及时调整生活方式。
- **作为企业主**，我希望查看全体员工的健康风险分布和管理成效报告，以便优化员工福利预算。
- **作为健康管理师**，我希望 AI 自动生成患者随访摘要和干预建议，以便我聚焦在高风险患者的深度管理上。
- **作为医生**，我希望在患者就诊时快速调取完整健康档案和 AI 解读，以便做出更准确的诊疗决策。
- **作为客服**，我希望 AI 客服 Agent 自动处理常规咨询，以便我专注于复杂投诉处理。
- **作为超级管理员**，我希望统一管理所有角色权限、审计操作日志，以便保障平台安全合规。

## 3. 系统范围与边界

### 3.1 In-scope（做什么）

- 患者健康档案的创建、维护、授权访问
- 多维度健康数据采集（体征监测、问卷评估、体检报告上传）
- AI Agent 驱动的健康问答、风险预警、方案生成
- 健康管理师 / 医生的随访与干预工作台
- 企业主的员工健康数据看板
- 客服工单系统（含 AI 自动处理）
- 超级管理员的平台运营与合规管理
- 多终端（Web / 移动 App / 小程序 / 穿戴设备）统一数据体验

### 3.2 Non-goals（不做什么）

- **不提供在线诊断**：AI 仅辅助，所有诊断结论由执业医生出具
- **不做医疗电商**：不在 v1.0 内集成药品购买或医疗器械销售
- **不做保险赔付**：不接入保险理赔流程（v2.0 规划）
- **不做医院 HIS 系统**：与 HIS 通过 HL7/FHIR 接口对接，不自建
- **不支持离线场景下的 AI 推理**（穿戴设备数据上传后在云端处理）

## 5. 多终端访问设计

### 5.1 终端矩阵

| 终端 | 主要目标用户 | 核心功能 | 技术方案 |
|------|------------|---------|---------|
| Web 浏览器 | 健管师、医生、企业主、超管 | 工作台全功能、数据看板、报告管理 | React / Vue SPA |
| iOS / Android App | 患者、健管师、客服 | 健康数据查看、任务打卡、AI 问答、消息通知 | React Native / Flutter |
| 微信小程序 | 患者（轻量入口） | 健康打卡、AI 轻问诊、报告查看、预约随访 | 微信原生小程序 |

- 桌面：≥ 1280px — 全功能布局
- 平板：768px ~ 1279px — 折叠侧栏
- 移动 Web：< 768px — 仅基础数据查看（引导下载 App）

## 6. AI 能力层设计

### 6.1 设计理念

采用 **大模型 + AI Agent + Skills** 三层架构：

```
[用户意图] → [Agent 路由层] → [选择 Skill] → [工具调用 / 知识库检索] → [大模型生成] → [响应用户]
```

- **大模型**：作为推理核心，支持切换（GPT-4o / 文心一言 / 混元等）
- **AI Agent**：有状态的自主任务执行者，可多轮对话、调用工具、管理上下文
- **Skills**：细粒度的可复用能力单元，类似函数，供 Agent 调用

### 6.2 Agent 清单

| Agent | 职责 | 主要 Skills | 触发场景 |
|-------|------|------------|---------|
| 健康问答 Agent | 回答患者健康咨询 | 知识库检索、指南查询、症状分析 | 患者主动发起咨询 |
| 个性化方案 Agent | 生成健康管理计划 | 目标设定、计划生成、饮食/运动推荐 | 建档后、定期复盘时 |
| 风险预警 Agent | 监测异常并触发预警 | 指标分析、风险评分、告警推送 | 体征数据上报时（实时触发） |
| 报告解读 Agent | 解析体检/检查报告 | OCR 提取、指标解读、异常标注 | 患者上传报告时 |
| 随访摘要 Agent | 自动生成随访摘要 | 历史数据汇总、关键变化提取、下次建议 | 健管师发起随访后 |
| 客服 Agent | 处理常规咨询和投诉 | 意图识别、知识库匹配、工单创建 | 客服渠道接收消息时 |

### 6.3 核心 Skills 规格

| Skill ID | Skill 名称 | 输入 | 输出 | 说明 |
|---------|------------|------|------|------|
| SK-001 | 症状初筛 | 症状描述文本 | 可能原因列表 + 建议就医等级 | 不作确诊，仅分诊参考 |
| SK-002 | 体检报告解析 | PDF/图片 | 结构化指标 JSON + 异常标注 | 支持 OCR + LLM 联合处理 |
| SK-003 | 健康风险评分 | 患者档案 + 体征历史 | 0-100 风险分 + 主要风险因素 | 基于规则 + 模型混合 |
| SK-004 | 个性化膳食建议 | 健康目标 + 禁忌 + 体重BMI | 7 日膳食计划 | 需结合营养知识库 |
| SK-005 | 运动方案生成 | 健康目标 + 体能水平 | 周运动计划 + 注意事项 | 含心率区间指导 |
| SK-006 | 随访摘要生成 | 随访记录 + 历史档案 | Markdown 格式摘要文本 | 供健管师一键确认 |
| SK-007 | 预警触发判断 | 实时体征数据 + 基线值 | 预警级别（低/中/高/紧急） | 驱动通知推送 |
| SK-008 | 情绪评估 | 量表答题结果（PHQ-9/GAD-7）| 情绪状态评分 + 建议 | 有自伤倾向时强制转人工 |
| SK-009 | 报告生成 | 企业 ID + 时间范围 | PDF 健康报告 | 供企业主下载 |
| SK-010 | 工单智能分类 | 客服消息文本 | 问题类型 + 优先级 + 建议回复 | 辅助客服，不替代人工复杂处理 |

### 6.4 AI 安全护栏

- **禁止输出**：明确诊断、处方建议、"停药/换药"指导
- **强制转人工**：情绪危机信号、超过 3 轮无法解决的医疗咨询
- **内容审核**：所有生成内容过安全过滤器，敏感词拦截
- **免责声明**：所有 AI 回复末尾自动附加"本内容仅供参考，不替代医疗诊断"

## 8. 各角色功能详规

---

### 8.1 患者端

#### 功能模块

**A. 健康档案**
- 注册/实名认证（手机号 + 身份证）
- 基础信息录入：姓名、性别、年龄、身高体重、慢病史、过敏史、家族史
- 体检报告上传（支持 PDF、图片），AI 自动解析并入档
- 授权管理：可授权/撤销特定健管师/医生查看档案

**B. 健康监测**
- 体征数据录入（手动输入 / 设备同步）：血压、血糖、心率、体重、血氧、睡眠
- 历史趋势折线图（7 日 / 30 日 / 3 月）
- 预警通知接收（Push / 短信 / 微信模板消息）

**C. AI 健康助手**
- 自然语言健康咨询（24 小时可用）
- 报告智能解读（上传后 3 分钟内出结果）
- 个性化健康建议（膳食、运动、睡眠）
- 情绪健康评估（PHQ-9 / GAD-7 量表）

**D. 健康计划执行**
- 查看健管师制定的健康计划
- 每日任务打卡（服药、运动、饮食记录）
- 完成度追踪（圆环进度图）
- 打卡提醒（自定义时间）

**E. 随访与沟通**
- 预约随访（选择健管师/医生 + 时间）
- 图文消息 / 短视频发送
- 查看随访记录历史
- 视频问诊入口（跳转第三方平台，如京东健康）

**F. 健康报告**
- 月度健康总结（AI 自动生成）
- 年度健康报告（PDF 下载）

#### 管理流程

```
注册实名 → 完善档案 → 绑定设备/上传报告
    → AI 初始健康评估（风险分）
    → 匹配健管师 → 制定健康计划
    → 日常监测打卡 → AI 实时分析
    → 预警触发 → 随访干预 → 阶段复盘
    → 更新计划（闭环循环）
```

---

### 8.2 健康管理师端

#### 功能模块

**A. 患者列表 & 工作台**
- 分配患者列表（支持按风险等级、依从性排序）
- 患者健康概览卡（关键指标 + 风险分 + 上次随访时间）
- 高风险患者优先队列（红色标注，需 24h 内触达）
- 批量操作（批量发送提醒、批量生成报告）

**B. 健康档案管理**
- 查看 / 补充患者档案（经患者授权）
- 健康评估录入（SOAP 笔记格式）
- 关联病史文件管理

**C. AI 辅助工作**
- 一键生成随访摘要（AI 汇总患者近期数据）
- 智能干预方案生成（填写患者目标后 AI 输出草稿，健管师审核修改）
- 下次随访建议（AI 基于趋势给出建议时间 + 关注点）

**D. 干预方案管理**
- 制定个性化健康计划（膳食 / 运动 / 用药提醒 / 生活方式）
- 计划模板库（可复用行业标准方案）
- 患者依从性追踪（任务完成率图表）

**E. 随访管理**
- 随访记录创建（记录内容 + 患者反馈 + 调整措施）
- 随访日历视图（日 / 周）
- 随访提醒设置（可配置随访间隔）
- 视频随访支持

**F. 数据分析**
- 个人服务看板（服务患者数、平均风险分、本月随访完成率）
- 患者群体健康趋势

#### 管理流程

```
接收患者分配通知 → 查阅档案与 AI 初评
    → 制定健康计划（AI 辅助） → 患者确认
    → 执行监测 & 提醒 → 依从性追踪
    → 定期随访（AI 自动生成摘要草稿）
    → 发现异常 → 升级医生 / 主动干预
    → 阶段评估 → 更新计划
```

---

### 8.3 医生端

#### 功能模块

**A. 患者全貌视图**
- 一页纸患者摘要（AI 从历史档案提炼）
- 主诉、现病史、既往史、用药史、过敏史
- 关键体征趋势图（可配置显示项）
- 历次就诊记录时间线

**B. 体检报告解读**
- AI 解析结果查看（含异常项高亮）
- 医生批注与修正（AI 解读后医生可标注）
- 历次报告对比（同指标多次结果并排）

**C. 问诊支持**
- 快速问诊记录（支持语音转文字）
- 诊断意见录入（SNOMED CT 编码辅助）
- 医嘱录入（随访计划、注意事项，不涉及处方）
- 检查单申请（内部流转，对接 HIS）

## 9. 健康管理全流程设计

### 9.1 全流程总览

```
【阶段 1：建档评估】
患者注册 → 实名认证 → 填写基础信息 → 上传体检报告
    → AI 自动解析报告 → 完成初始健康评估（风险分）
    → 匹配健管师

【阶段 2：方案制定】
健管师查阅档案 + AI 摘要 → 与患者沟通健康目标
    → 调用"个性化方案 Agent" → 生成计划草稿
    → 健管师调整确认 → 患者签字确认计划

【阶段 3：执行监测】
患者日常体征录入（设备自动上报 / 手动输入）
    → 风险预警 Agent 实时分析
    → 低风险：存档 + 趋势图更新
    → 中风险：APP 推送建议 + 健管师可见
    → 高风险：短信 + Push + 健管师 24h 内随访
    → 紧急：立即通知医生 + 提示 120

【阶段 4：随访干预】
健管师发起随访（视频/图文）
    → AI 自动生成随访前摘要（近期数据 + 变化）
    → 随访中：记录内容、患者反馈
    → 发现需要医生介入：转诊
    → 医生接诊 → 诊断意见回传 → 健管师执行调整

【阶段 5：复盘优化】
阶段健康报告生成（AI 汇总）
    → 患者 / 健管师共同回顾
    → 健康计划更新 → 进入下一轮执行周期
    → 企业主查看员工整体健康报告
```

### 9.2 关键流转规则

| 场景 | 触发条件 | 执行动作 | 责任方 |
|------|---------|---------|-------|
| 低风险预警 | 单指标轻度偏离基线 | APP 内提示 + 记录 | AI 自动 |
| 中风险预警 | 指标连续 3 天偏离 / 综合风险分 > 60 | 推送通知 + 健管师工作台标红 | AI + 健管师 |
| 高风险预警 | 核心指标明显异常 / 风险分 > 80 | 短信 + 推送 + 健管师 24h 内必须响应 | 健管师（SLA 强制） |
| 紧急预警 | 血压 > 180/120 / 血氧 < 90% | 立即推送 + 弹窗 + 提示拨打急救 | 系统 + 医生 |
| AI 无法处理 | 连续 3 轮未解决 / 情绪危机信号 | 强制转人工健管师/客服 | 系统自动转接 |
| 患者不活跃 | 14 天无打卡记录 | 自动触发关怀推送 | AI 自动 |

## 12. 安全与合规

### 12.1 数据安全

- **传输加密**：所有接口强制 HTTPS（TLS 1.3），WebSocket 使用 WSS
- **存储加密**：敏感字段（身份证、真实姓名、手机号）AES-256 加密存储
- **访问控制**：JWT + RBAC，Token 有效期 2 小时，RefreshToken 7 天
- **数据脱敏**：企业主看板数据全部脱敏；API 日志自动脱敏敏感字段
- **SQL 防注入**：ORM 参数化查询，禁止拼接 SQL

### 12.2 隐私合规

- **个人信息保护法（PIPL）**：
  - 注册时明示收集范围，用户主动勾选同意
  - 用户可申请导出 / 删除个人数据（30 天内处理）
  - 健康数据属于敏感个人信息，单独获取明示同意
- **最小化原则**：每个角色仅获取完成工作必要的数据
- **授权链路**：患者明确授权后，健管师/医生方可访问档案（记录授权时间、范围）

### 12.3 医疗特殊合规

- AI 输出统一加免责声明，禁止直接诊断
- 情绪危机自动转人工，记录完整处置链
- 医生录入的诊断意见受法律保护，禁止随意修改（仅可追加批注）
- 体检报告原始文件永久存档，不可删除
