元数据
Metadata — Data About Data
元数据基础
什么是元数据？
元数据是"描述数据的数据"——它为数据提供上下文、结构与语义，使数据可被理解、检索与互操作。
📐
结构性元数据
描述数据的组织方式：表结构、字段类型、关系模型、文件格式（CSV、Parquet、DICOM）
🏷️
描述性元数据
描述数据内容：标题、摘要、创建时间、作者、关键词、主题分类
⚙️
管理性元数据
数据的生命周期信息：版本、访问权限、保留期限、数据血缘（Lineage）
🔬
技术性元数据
系统级属性：文件大小、编码格式、校验和、分区键、压缩算法
🌐
语义元数据
赋予数据意义：本体（Ontology）、受控词表、代码字典（Code Dictionary）
🔗
操作性元数据
运行时信息：ETL日志、处理时间、数据质量指标、SLA合规记录
元数据基础
元数据三层架构模型
从业务语义到物理存储，元数据贯穿数据全生命周期，是数据治理的基础。
业务层（Business Layer）
业务术语、KPI定义、数据域划分、数据产品目录；面向业务用户，强调语义与可读性
↓
逻辑层（Logical Layer）
实体关系模型、数据流图、数据字典、血缘图谱；面向数据架构师和分析师
↓
物理层（Physical Layer）
表结构、索引、分区、压缩格式、存储位置；面向工程师和DBA

通用数据模型 CDM
Common Data Model
CDM 概述
什么是通用数据模型？
CDM 通过统一的结构和语义标准，使来自不同来源的数据能够按照相同的方式进行分析，实现跨机构、跨系统的互操作。
  • 1
    标准化结构
    定义统一的表名、字段名和关系，消除命名差异
  • 2
    语义规范化
    使用标准词汇（ICD、SNOMED、RxNorm）对概念进行统一编码
  • 3
    可重用分析
    一套分析代码（SQL、R、Python）可在不同机构的CDM上运行
  • 4
    数据质量保障
    内置数据质量检核规则，确保数据的完整性与准确性

2.1
CDISC 标准体系
Clinical Data Interchange Standards Consortium
CDISC 标准
CDISC 组织与标准族
CDISC（临床数据交换标准联盟）成立于1997年，其标准是FDA、PMDA、NMPA等全球监管机构要求电子申报的核心规范。
SDTM — 研究数据制表模型
Study Data Tabulation Model
原始临床数据的标准化组织方式，用于向监管机构提交原始研究数据，每个数据集对应一个域（Domain）
ADaM — 分析数据模型
Analysis Data Model
在SDTM基础上派生的分析就绪数据集，直接支持统计分析（如ADSL、ADAE、ADLB），含分析变量与标志变量
CDASH — 数据采集协调标准
Clinical Data Acquisition Standards Harmonization
定义CRF表单字段的标准名称和格式，从源头保证数据与SDTM的对应关系
CDISC CT — 受控术语
Controlled Terminology
标准化代码集（Code List），每季度更新，确保字段值的一致性（如 Y/N/UNK 性别代码 M/F/U 等）

SDTM 将研究数据按主题分组为若干标准域。每个域包含固定结构：域标识符（2字母）+ 标准变量集。

SDTM 变量命名规则：前缀 = 域标识符
每个域的变量以域名缩写为前缀，如 AE 域的变量：AETERM（不良事件术语）、AESTDTC（开始日期）、AEENDTC（结束日期）、AESER（是否严重）、AETOXGR（毒性分级）。日期格式统一使用 ISO 8601 字符型（YYYY-MM-DD）。
CDISC / SDTM 规则
SDTM 核心规则与必选变量
每个 SDTM 数据集必须遵守以下命名、结构与内容规范，违规将导致电子申报被拒绝。
五类必选变量（Required）
变量含义示例
STUDYID研究标识符ABC-001
DOMAIN域标识符AE
USUBJID受试者唯一IDABC-001-001-001
--SEQ序列号AESEQ = 1,2,3
--TERM观测事件名称AETERM
⚠️ 常见不符合项
① 日期用数值而非字符 ② 使用非标准域名 ③ 缺少 Define.xml ④ 受控术语未使用标准代码集 ⑤ SUPPQUAL 补充数据集结构错误
受控术语（Controlled Terminology）使用
  • ✓
    性别：M / F / U（不得使用男/女/0/1）
  • ✓
    是/否标志：Y / N（不得使用 Yes/No/1/0）
  • ✓
    不良事件结局：RECOVERED/RESOLVED、FATAL等
  • ✓
    AE 编码使用 MedDRA 词库，实验室异常使用 NCI CTCAE 分级
  • ✓
    日期必须用字符型 ISO 8601：2024-03-15，不完整日期：2024-03
CDISC / ADaM
ADaM 分析数据模型
ADaM 是从 SDTM 派生的分析就绪数据集，每个分析都能追溯到 SDTM 原始数据，满足 ALCOA 原则（可归因、清晰、同步、原始、准确）。
ADSL — 受试者汇总
每名受试者一行，包含人口学、分组、安全性人群标志（SAFFL）、ITT人群（ITTFL）、入组日期等
ADAE — 不良事件
基于 AE 域派生，添加分析标志如 TRTEMFL（治疗期间发生标志）、ANL01FL 等
ADLB — 实验室
基于 LB 域，包含基线值（BASE）、变化值（CHG）、百分比变化（PCHG）及正常范围标志
ADEFF — 有效性
疗效终点数据集，含主要终点、次要终点，支持 ANCOVA、Kaplan-Meier 等统计分析
ADTTE — 生存分析
Time-to-Event 数据集，包含生存时间（AVAL）、删失标志（CNSR）、事件标签（EVNTDESC）
ADQS — 问卷量表
量表评分数据，支持纵向分析，含访视标识（AVISIT/AVISITN）和评分变化
ADaM 三类核心结构
ADSL（每受试者一行）· BDS（基本数据结构，每受试者每参数每时间点一行）· OCCDS（事件发生数据结构，用于AE/CM等重复事件记录）
2.2
OMOP CDM
Observational Medical Outcomes Partnership
OMOP CDM
OMOP CDM — 真实世界数据基础架构
OMOP CDM（v5.4）由 OHDSI 联盟维护，覆盖全球 800+ 数据库、35亿+患者记录，是真实世界证据（RWE）研究的主流标准。
核心临床表（Clinical Tables）
PERSON
患者人口学信息（性别、生日、种族、出生地），每人一行，唯一标识 person_id
VISIT_OCCURRENCE
就诊记录（门诊/住院/急诊），包含时间、地点、类型
CONDITION_OCCURRENCE
诊断记录，ICD 编码统一映射为 SNOMED-CT concept_id
DRUG_EXPOSURE
药物暴露记录，RxNorm/ATC 标准编码，含剂量、频次、给药途径
MEASUREMENT / OBSERVATION
检验检查结果及临床观测，LOINC 编码，含数值、单位、正常范围
标准词汇体系（Vocabulary Tables）
词汇覆盖领域
SNOMED-CT诊断、临床发现、手术
LOINC检验、检查、观测指标
RxNorm药物（成分级）
ATC药物解剖治疗化学分类
ICD-9/10疾病分类（映射至SNOMED）
CPT4/OPCS医疗操作与手术编码
💡 OMOP 的核心思想：概念映射
将源系统中的任意编码（ICD、院内代码）映射到统一的 concept_id，所有分析基于 concept_id 而非原始编码运行，实现了跨机构可重复研究。
OMOP CDM 规则
OMOP 核心规则与分析工具
OMOP 的规则围绕"每行一个临床事件"展开，配合 OHDSI 开源工具链实现大规模分布式研究。
核心规则
  • R1
    所有日期使用 DATE 类型，时间使用 DATETIME，时区统一
  • R2
    concept_id = 0 表示未知/未映射，不得省略字段，应显式填 0
  • R3
    每个临床事件通过 visit_occurrence_id 与就诊关联（可选但推荐）
  • R4
    standard_concept = 'S' 的 concept 才能用于分析；'C' 为分类概念
  • R5
    PERSON 表的 person_id 必须是去标识化主键，不得使用真实患者ID
ETL 转换流程
源数据 → 编码映射（Usagi工具）→ 概念关系遍历 → OMOP表填充 → DQD数据质量检查（DataQualityDashboard）→ ACHILLES特征描述
OHDSI 工具链
工具功能
ATLAS队列定义、特征化、倾向评分
ACHILLES数据特征描述与质量报告
Usagi源编码与标准概念映射
HADESR包：PatientLevelPrediction, CohortMethod, EvidenceSynthesis
DQDDataQualityDashboard 数据质量仪表板

SPSS / SAS 数据集导出
Statistical Software Compliant Dataset Export
统计软件导出
SAS 传输格式（XPT）规范
FDA 要求所有 NDA/BLA 申报的 SDTM 和 ADaM 数据集以 SAS V5 Transport Format（.xpt）提交，该格式有严格的技术限制。
SAS XPT v5 技术限制
属性限制
数据集名（Dataset Name）≤ 8 个字符，大写
变量名（Variable Name）≤ 8 个字符，无特殊字符
变量标签（Label）≤ 40 个字符
字符型长度（Char Length）≤ 200 字节
数值型（Numeric）IEEE 754 双精度，8字节
日期格式SAS 日期值（距1960-01-01的天数）
文件大小单个 .xpt 建议 ≤ 5GB
💡 SAS XPT v8 扩展
FDA 2023年更新接受 SAS V8 Transport（.xpt8），支持变量名最长 32 字符、标签最长 256 字符，推荐新项目使用 v8 格式。
Python 生成 SAS XPT 示例
import pandas as pd import pyreadstat # 读取 SDTM AE 数据 ae_df = pd.read_csv("ae_sdtm.csv") # 变量标签字典（≤40字符） col_labels = { "STUDYID": "Study Identifier", "USUBJID": "Unique Subject Identifier", "AETERM": "Reported Term for AE", "AESTDTC": "Start Date/Time of AE", "AESER": "Serious AE", } # 导出为 SAS XPT v5 pyreadstat.write_xport( ae_df, "ae.xpt", column_labels=col_labels, file_label="Adverse Events" )
统计软件导出
SPSS .sav 数据集导出规范
SPSS .sav 格式广泛用于医学统计分析，正确的变量类型、值标签和缺失值声明是保证分析准确性的关键。
SPSS 变量类型规范
数据类型SPSS类型注意事项
分类变量（性别/分组）Numeric + 值标签1=男,2=女；不得用字符
连续变量（年龄/体重）Numeric (F8.2)保留小数位数一致
日期时间Date (ADATE8)使用 SPSS 日期格式
文本/描述String (A80)长度固定，避免尾随空格
系统缺失Sysmis (.)区分系统缺失与用户缺失
⚠️ 缺失值处理规范
应区分：① 系统缺失（Sysmis，未收集）② 用户定义缺失（如 99 = 拒绝回答，-1 = 未知）。在 SPSS 中通过 MISSING VALUES 命令声明用户缺失，确保统计函数正确排除缺失值。
Python 生成 SPSS .sav 示例
import pandas as pd import pyreadstat df = pd.DataFrame({ 'USUBJID': ['001-001', '001-002'], 'AGE': [45, 62], 'SEX': [1, 2], # 1=M 2=F 'TRT01P': [1, 2], # 1=Drug 2=Placebo 'AVAL': [8.2, 6.5], }) # 值标签 val_labels = { 'SEX': {1: 'Male', 2: 'Female'}, 'TRT01P': {1: 'Drug A', 2: 'Placebo'}, } # 变量标签 var_labels = { 'USUBJID': 'Subject ID', 'AGE': 'Age (years)', 'SEX': 'Sex', 'TRT01P': 'Planned Treatment', 'AVAL': 'Analysis Value', } pyreadstat.write_sav( df, "adsl.sav", variable_value_labels=val_labels, column_labels=var_labels )
统计软件导出
数据集导出质量检查清单
导出前必须完成以下检核，确保统计分析软件正确读取并产生可重现的分析结果。
SAS XPT 检查要点
  • ✓
    数据集名 ≤ 8 字符，变量名 ≤ 8 字符（v5）
  • ✓
    所有变量均有 LABEL，中文标签改为英文
  • ✓
    日期变量赋予 SAS 日期 FORMAT（如 DATE9.）
  • ✓
    使用 PROC CONTENTS 验证类型与标签
  • ✓
    字符变量不含 NULL，替换为空字符串 ""
  • ✓
    与 Define.xml 中的变量顺序和类型一致
SPSS .sav 检查要点
  • ✓
    所有分类变量已设置值标签（Value Labels）
  • ✓
    缺失值已用 Missing Values 命令声明
  • ✓
    变量测量尺度正确（Scale/Ordinal/Nominal）
  • ✓
    字符变量宽度足够，无截断
  • ✓
    使用 CODEBOOK 命令或 Frequencies 验证编码
  • ✓
    文件编码设为 UTF-8（SPSS 29+）
通用最佳实践：数据集文档化三件套
① 数据字典（变量名、标签、类型、单位、受控词表） · ② 编码手册（值标签对照表，含缺失值说明） · ③ 分析计划书（SAP，说明每个分析的数据集来源和派生规则）

CDISC vs OMOP — 选择指南
两种标准并非竞争关系，而是在数据生命周期的不同阶段发挥互补作用。许多机构同时维护两套标准数据集。
维度CDISC (SDTM/ADaM)OMOP CDM

数据来源 EDC 临床试验 CRF 表单 EHR、HIS、医保、药房

时间序列 以访视为基准（协议驱动） 以事件发生时间为基准

核心术语集
医疗数据标准术语集详解
标准化的术语集是实现跨系统数据互操作的关键。以下介绍 CDISC 与 OMOP 中使用的主流术语集。
MedDRA
Medical Dictionary for Regulatory Activities
FDA/EMA 等监管机构要求使用的不良事件编码系统
· 层级结构:HLG → PT → LLT (5 层)
· 覆盖领域：疾病、手术、检验、药品
· CDISC 标准:AE/CM域必用
LOINC
Logical Observation Identifiers Names and Codes
实验室检查、生命体征观测的国际标准编码
· 覆盖 58 万 + 观测项目
· 包含：名称、成分、性质、时间点、方法
· OMOP 核心:MEASUREMENT 表必用
RxNorm
Drug Name Repository
美国国家医学图书馆 (NLM) 维护的标准药物编码
· 覆盖 24 万 + 药物概念
· 支持：药品成分、剂量、剂型、给药途径
· OMOP 核心:DRUG_EXPOSURE 表必用
SNOMED-CT
Systematized Nomenclature of Medicine Clinical Terms
全球最全面的临床医学术语集
· 35 万 + 临床概念，82 万 + 术语
· 覆盖诊断、症状、手术、设备
· OMOP 核心:CONDITION_OCCURRENCE 表必用
ICD-9/10/11
International Classification of Diseases
WHO 发布的疾病分类标准
· ICD-10: 1.2 万 + 疾病代码
· ICD-11: 2022 年启用，支持电子健康记录
· 医保报销、流行病学统计必用
NCI CTCAE
Common Terminology Criteria for Adverse Events
美国国家癌症研究所不良事件分级标准
· 5 级严重程度分级 (1-5)
· 覆盖肿瘤治疗常见不良事件
· CDISC 标准：肿瘤试验 AETOXGR 字段
术语集映射机制
跨术语集的映射策略与工具
源系统中的本地编码需要通过映射工具转换到标准术语集，这是实现数据互操作的核心环节。
映射层级与关系类型

CDISC 数据质量管理
CDISC：侧重于数据管理合规
CDISC 的数据质量要求围绕监管申报展开，强调数据从采集到提交的全过程可追溯性与合规性。
核心质量维度 (ALCOA+)
  • A
    Attributable (可归因)
    每条数据可追溯到原始记录与录入人
  • L
    Legible (清晰可辨)
    数据格式标准化，无歧义表达
  • C
    Contemporaneous (同步记录)
    数据采集与试验进程时间同步
  • O
    Original (原始记录)
    保留数据最初记录形态
  • A
    Accurate (准确无误)
    通过双重录入、逻辑检核确保准确性
数据管理工具链
① CDISC Validator 自动检查 SDTM/ADaM 合规性 · ② Define.xml 描述数据集结构 · ③ Data Review Initiative (DRI) 人工审核 · ④ CDMP 流程文档化

OMOP 数据评估体系
OMOP：侧重于数据质量评估
OMOP CDM 的数据评估方法更加系统化、自动化，通过 ACHILLES 和 DQD 工具实现大规模数据的快速质量诊断。
数据质量评估五维度
维度指标示例
完整性NULL 值比例、必填字段缺失率
有效性概念编码有效性、外键约束
一致性性别与出生性别一致性
及时性数据更新延迟天数
准确性逻辑矛盾检测 (死亡日期 < 出生日期)
