## 执行摘要

本产品是一套一体化的临床试验管理平台，整合 CTMS（临床试验管理系统）、EDC（电子数据采集系统）、IWRS（交互式随机化与药物供应管理系统）以及医生个人病历夹四大核心模块。系统采用微服务架构，底层数据库符合 CDISC 标准，支持拖拉拽式 eCRF 设计，实现从试验管理、数据采集、随机化到医生个人患者管理的端到端数字化解决方案。

**核心价值主张**：
- **一体化整合**：四大系统共用数据库，消除数据孤岛，提升协作效率
- **标准合规**：底层数据模型符合 CDISC/SDTM 标准，确保数据质量与监管合规
- **灵活配置**：拖拉拽式表单设计，CDASH 标准字段库，快速响应研究需求
- **AI 赋能**：全流程 AI 辅助开发与测试，加速交付周期
- **Saas 化部署**：多租户架构，支持快速扩展与持续迭代

## 产品愿景与目标

### 愿景

成为全球领先的智能化临床试验数字化平台，通过技术手段降低临床试验成本、提升数据质量、加速新药上市，同时为医生提供便捷的患者管理工具，实现临床试验与日常医疗的深度融合。

### 目标（12-18 个月）

| 目标类型 | 具体指标 | 目标值 |
|---------|---------|-------|
| **用户体验** | eCRF 表单设计时间（从需求到上线） | 减少 60% |
| **数据质量** | 数据核查问题发现周期 | 减少 50% |
| **合规性** | CDISC 标准符合率 | ≥95% |
| **效率提升** | 数据锁库前清理时间 | 减少 40% |
| **成本节约** | 单试验系统实施成本 | 减少 30% |
| **用户覆盖** | 支持并发试验数量 | ≥100 个 |

### 非目标（Non-Goals）

1. **不涉及实验室 LIS 系统深度集成**：仅支持实验室数据导入，不提供完整的 LIS 功能
2. **不提供影像归档与通信（PACS）功能**：仅支持影像数据链接引用
3. **不支持电子签名证书颁发**：对接第三方 CA 机构，不自建 CA
4. **不提供统计分析功能**：仅支持 SDTM/ADaM 数据导出，统计分析由专业软件完成
5. **暂不支持移动端原生应用**：第一阶段采用响应式 Web 设计

**原因说明**：上述功能属于相邻领域或可由第三方专业工具更好实现，聚焦核心能力确保 v1.0 按时交付。

## 用户角色与场景

**用户画像**：
- 三甲医院科室主任或资深医师

- 审批方案偏离（Protocol Deviation）
- 审核质疑（Query）并回复

- 查看患者入组进度与随机化状态

- 医院或 CRO 派驻现场人员

**核心场景**：
- 录入患者 eCRF 数据
- 回复数据质疑（Query）
- 管理患者访视日程
- 打印/导出知情同意书等文件
- 提交工时记录

**用户画像**：
- 申办方或 CRO 数据管理团队
- 负责 eCRF 设计、数据质量控制

- 拖拉拽设计 eCRF 表单

#### 5. 药物供应管理员（Drug Supply Manager）

**用户画像**：
- 负责试验用药管理与分配
- 管理随机化方案
- 监控药物库存与配送

**核心场景**：
- 配置随机化方案
- 管理药物库存与配送
- 执行随机化与药物分配
- 管理药物回收与销毁
- 查询随机化日志

#### 6. 医生（个人病历夹用户）

**用户画像**：
- 临床医生个人使用
- 管理日常患者病历
- 需要灵活自定义表单

**核心场景**：
- 创建患者档案
- 拖拉拽自定义数据采集表单
- 引用 EDC 中已有模板
- 查看患者历史数据与趋势
- 导出患者病历报告

#### 7. 系统管理员（System Administrator）

**用户画像**：
- IT 运维团队

## 系统架构总览

### 技术架构原则

1. **微服务架构**：各功能模块独立部署，松耦合，支持独立扩展
2. **统一数据层**：共用数据库，通过 API Gateway 统一暴露接口
3. **多租户设计**：数据隔离与共享平衡，支持 Saas 化运营
4. **标准优先**：数据模型遵循 CDISC 标准，API 遵循 RESTful 规范
5. **AI 友好**：代码与测试全流程 AI 辅助，自动化率高

### 数据库设计原则

1. **CDISC SDTM 遵循**：
   - 核心数据集：DM（受试者）、AE（不良事件）、EX（暴露）、DS（观察结果）、CM（合并用药）等
   - 域命名规范：三字母域名 + 变量名
   - 元数据管理：通过定义数据集（Define.xml）记录数据结构

2. **多租户隔离**：
   - 每个表包含 `tenant_id` 字段
   - 通过 Row-Level Security (RLS) 或应用层过滤实现数据隔离
   - 共享系统表（如用户、权限）与租户表分离

3. **审计追踪**：
   - 所有数据变更记录审计日志（谁、何时、何字段、原值、新值）
   - 符合 21 CFR Part 11 电子记录与电子签名要求
   - 审计日志不可篡改，独立存储

## 功能模块详细设计

### 模块一：EDC（电子数据采集系统）

#### 1.1 eCRF 表单设计器

**功能描述**：拖拉拽式表单设计器，支持快速创建符合 CDASH 标准的 eCRF 表单。

**核心功能**：

##### 字段库（CDASH 标准）

**预置字段类型**：
- **基本类型**：
  - 单行文本（Single Line Text）
  - 多行文本（Multi-line Text）
  - 数字（Number）
  - 日期（Date）
  - 日期时间（Date Time）
  - 下拉选择（Dropdown）
  - 单选按钮（Radio Button）
  - 复选框（Checkbox）
  - 计算字段（Calculated Field）

- **医疗专用类型**：
  - MedDRA 编码选择器
  - WHO Drug 药品选择器
  - 实验室数值 + 单位
  - 范围值（最小值 - 最大值）
  - 是/否/不适用（Y/N/NA）

**字段属性配置**：
```typescript
interface CrfFormField {
  // CDASH 标准字段名（英文）
  variableName: string;        // 例：AETERM, AESER
  // 中文标签
  displayLabel: string;        // 例：不良事件名称
  // 字段类型
  fieldType: FieldType;
  // 是否必填
  required: boolean;
  // 验证规则
  validationRules: ValidationRule[];
  // CDASH 元数据
  cdashDefinition?: string;
  // SDTM 映射
  sdtmMapping?: {
    domain: string;            // 例：AE
    variable: string;          // 例：AETERM
  };
  // 显示顺序
  sortOrder: number;
  // 是否重复项
  repeatable: boolean;
  // 重复项最大次数
  maxRepetitions?: number;
}
```

##### 表单设计器界面

**布局方式**：
- **页签（Tab）**：对应 eCRF 的不同页面（如人口学、不良事件、合并用药）
- **区域（Region）**：页签内的逻辑分组
- **项目（Item）**：具体字段

**拖拉拽功能**：
1. 左侧面板：字段库（按类别分组）
2. 中间画布：表单结构可视化
3. 右侧面板：字段属性配置

**实时预览**：设计时实时预览表单渲染效果

##### 模板管理

**模板类型**：
- **系统模板**：预置常用模板（人口学、生命体征、不良事件等）
- **项目模板**：针对特定研究项目创建
- **个人模板**：医生个人自定义模板

**模板引用**：
- 医生病历夹可直接引用 EDC 模板
- 支持模板版本管理
- 模板克隆与继承

**需求规格**：

| 需求 ID | 描述 | 验收标准 |
|-------|------|---------|
| EDC-FORM-001 | 用户可以从字段库拖拽字段到表单画布 | 拖拽操作流畅，字段正确放置到目标位置 |
| EDC-FORM-002 | 字段英文名自动遵循 CDASH 命名规范 | 系统自动校验英文名格式，冲突时提示 |
| EDC-FORM-003 | 字段中文名必须填写 | 保存前校验，未填写中文标签禁止保存 |
| EDC-FORM-004 | 支持字段属性配置（必填、验证规则、默认值等） | 属性面板完整，配置后即时生效 |
| EDC-FORM-005 | 支持表单版本管理 | 每次保存生成新版本，支持版本对比与回滚 |
| EDC-FORM-006 | 支持模板导出/导入（JSON 格式） | 导出的 JSON 符合 schema，导入可还原表单 |

#### 1.2 数据录入

**功能描述**：CRC/研究者录入受试者数据的界面与流程。

**核心功能**：

##### 数据录入界面

- **受试者列表**：显示当前项目下所有受试者状态（筛fail/已入组/已完成/脱落）
- **受试者详情**：按访视/页签展示 eCRF 表单
- **访视导航**：顶部导航条快速切换访视
- **数据状态**：标记已录入/已审核/有质疑的数据

##### 数据录入体验

**实时保存**：
- 每 30 秒自动保存
- 字段失焦时即时保存
- 保存状态可视化（保存中/已保存/保存失败）

**数据验证**：
- **即时验证**：字段失焦时立即校验
- **提交验证**：保存时执行所有核查规则
- **验证提示**：错误用红色标记，警告用黄色标记

**数据质疑（Query）管理**：
- 质疑列表视图
- 质疑状态：新质疑/回复中/已解决
- 回复质疑时可附加注释

**需求规格**：

| 需求 ID | 描述 | 验收标准 |
|-------|------|---------|
| EDC-ENTRY-001 | 用户录入数据时系统自动保存 | 30 秒间隔自动保存，网络中断时本地缓存 |
| EDC-ENTRY-002 | 数据验证错误即时提示 | 验证失败时字段红色边框，显示错误信息 |
| EDC-ENTRY-003 | 用户可查看并回复质疑 | 质疑列表清晰，回复后状态更新 |
| EDC-ENTRY-004 | 支持数据修改历史查看 | 点击字段可查看该字段所有修改记录 |
| EDC-ENTRY-005 | 支持键盘快捷键操作 | Tab 键切换字段，Ctrl+S 保存等 |

#### 1.3 数据核查（Edit Check）

**功能描述**：配置和执行数据核查规则，保证数据质量。

**核查规则类型**：

##### 域内核查（Within-Record）
```javascript
// 示例：不良事件发生时间必须在入组时间之后
rule: "AEAESDT >= DMBIRTHDT + AGEUPD"
severity: "ERROR"
message: "不良事件发生时间不能早于受试者出生日期"
```

##### 跨域核查（Cross-Domain）
```javascript
// 示例：实验室异常值应在 AE 中有记录
rule: "EXISTS(LB WHERE LBORRESN > UPPER_LIMIT) AND NOT EXISTS(AE WHERE AETERM = '实验室检查异常')"
severity: "WARNING"
message: "请确认是否需要记录相关不良事件"
```

##### 医学逻辑核查
- 用药剂量合理性
- 生命体征范围检查
- 实验室值医学范围

**规则配置界面**：
- 可视化规则构建器（无需编程）
- 支持 SQL 表达式高级用户
- 规则测试工具（用样本数据验证规则）

#### 1.4 SDTM 数据导出

### 模块三：IWRS（交互式随机化与药物供应管理系统）

#### 3.1 随机化方案配置

**功能描述**：配置灵活多样的随机化方案，满足复杂研究设计需求。

**支持的随机化类型**：

##### 简单随机化
```json
{
  "type": "SIMPLE",
  "arms": [
    {"armCode": "A", "probability": 0.5},
    {"armCode": "B", "probability": 0.5}
  ]
}
```

##### 区组随机化
```json
{
  "type": "BLOCK",
  "blockSize": [4, 6, 8],  // 随机区组大小
  "arms": ["A", "B"],
  "randomBlockSizes": true
}
```

##### 分层随机化
```json
{
  "type": "STRATIFIED",
  "stratificationFactors": [
    {"factorName": "SITE", "values": ["SITE001", "SITE002", "SITE003"]},
    {"factorName": "DISEASE_STAGE", "values": ["I", "II", "III"]}
  ],
  "withinStratum": {
    "type": "BLOCK",
    "blockSize": 4
  }
}
```

##### 动态随机化
```json
{
  "type": "DYNAMIC",
  "balancingFactors": ["SITE", "DISEASE_STAGE"],
  "method": "MINIMUM_SUM"  // 最小化方法
}
```

| 药物暴露 | EX | Exposure |

- 表单结构符合 CDASH 模板

- **系统验证**：系统需通过验证（CSV）

#### ICH GCP E6(R2)

- 数据质量与完整性
- 受试者权益保护
- 试验方案遵循
- 安全性报告

#### GDPR/HIPAA

- 数据隐私保护
- 数据最小化原则
- 数据主体权利（访问、删除、导出）
- 数据安全加密
