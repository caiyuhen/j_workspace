# MedA Wave 4 阶段入口枢纽页设计文档

> 设计日期：2026-08-04
> 设计范围：科研流程阶段入口枢纽页
> 适用阶段：Wave 4 设计确认

## 1. 设计目标

本设计文档用于定义 MedA 在 `Wave 4` 阶段的科研流程阶段入口页方案。该阶段的任务不是直接深做单个科研模块，而是把 `Wave 3` 中首页阶段卡片后的骨架承接页升级成真正可进入、可导航、可继续工作的 `阶段入口枢纽页`。

本阶段的核心目标有三项：

- 把首页阶段卡片与后续真实科研能力连接起来
- 在保持 `Hermes` 工作台壳层稳定的前提下，补齐统一的阶段入口层
- 用一套 `通用阶段壳` 承接六个阶段，避免过早分叉成六套页面结构

## 2. 已确认设计决策

- `Wave 4` 优先对象为 `科研流程模块入口页`
- 入口页采用 `阶段入口枢纽` 结构，而非任务板优先或产物优先
- 六个阶段共用同一套 `通用阶段壳`
- 中间主区优先突出 `子入口导航`
- 右侧栏优先承载 `阶段助手 + 下一步建议`
- 本波不深做单个阶段，不在入口页内直接展开重业务工作区

## 3. 核心定位

阶段入口页属于工作台体系内的第二层页面。它不是首页，也不是最终深业务页，而是首页与阶段内真实能力之间的统一枢纽层。

该页面主要解决三个问题：

- 当前进入的是哪个科研阶段
- 这个阶段下面有哪些子入口可以进入
- 下一步最值得做什么

如果一个功能不能帮助回答这三个问题，就不应优先放入 `Wave 4` 的阶段页核心区域。

## 4. 总体设计原则

- `Hermes` 壳层连续：阶段页继续复用工作台壳层，不做成独立产品式跳转
- 通用结构优先：六个阶段共享同一页面框架，只替换内容数据
- 入口导航优先：中间主区首先解决“可进入什么”，而不是“展示多少统计”
- 下一步优先：阶段助手与主 CTA 用于缩短用户从入口到执行的路径
- 双端一致优先：Web 与 Desktop 保持同一信息架构与内容语义
- 可追溯优先：任务、产物、建议动作都必须保留项目上下文与后续承接能力

## 5. 方案取舍结论

### 5.1 阶段页形态取舍

本轮评估过三种阶段页形态：

- `A. 阶段入口枢纽`
- `B. 任务板优先`
- `C. 产物与证据优先`

最终采用 `A. 阶段入口枢纽`，原因如下：

- 最适合作为首页与深业务页之间的中间层
- 能稳定承载六个阶段而不强依赖完整任务系统
- 既能表达阶段目标，也能承载任务与产物摘要，不会过早偏向某一侧

### 5.2 推进策略取舍

本轮评估过三种推进方式：

- 六阶段共用通用壳
- 先深做一个阶段
- 通用壳加单阶段强化

最终采用 `六阶段共用通用壳`，原因如下：

- 能最快建立统一阶段入口层
- 最有利于双端一致和后续配置化扩展
- 能避免在 `Wave 4` 过早陷入单阶段深业务范围

### 5.3 主区重点取舍

中间主区最终选择 `子入口导航优先`，而不是最近任务优先或最近产物优先。原因是本阶段页面的职责是“把用户送进正确的下一层能力”，而不是替代任务页或产物页本身。

### 5.4 右侧栏取舍

右侧栏最终选择 `阶段助手 + 下一步建议`，而不是待办优先或说明优先。这样更符合入口页定位，也能把阶段内推荐动作和高频捷径显式放在右侧推进区。

## 6. 页面结构

阶段入口页继续沿用 `Wave 3` 工作台壳层，只替换中间主区和右侧栏内容。

页面结构保持四段：

1. `左侧窄导航`
2. `左侧项目上下文面板`
3. `中间主区`
4. `右侧栏`

### 6.1 左侧窄导航

左侧窄导航与 `Wave 3` 保持一致，继续作为全局模块切换入口：

- 工作台
- 项目
- 数据 / 资料
- Agent
- 产物
- 管理

阶段页不在左侧窄导航里新开额外层级，避免全局导航复杂化。

### 6.2 左侧项目上下文面板

左侧项目上下文面板继续展示：

- 当前项目名称
- 项目标识
- 所属机构
- 当前阶段
- 项目切换入口
- 相关模块快捷入口

在阶段页里，这个面板继续承担“我现在在哪个项目”的职责，不承担阶段深内容展示。

### 6.3 中间主区

中间主区是 `Wave 4` 的核心变化点，采用三层结构。

#### 顶部阶段摘要层

用于说明当前进入的阶段及本阶段目标。建议包含：

- 阶段名称
- 所属项目
- 当前阶段状态
- 本阶段一句话目标
- 一个主 CTA，例如“进入当前最优先子入口”

约束：

- 主 CTA 保持单一，避免再次制造选择过载
- 顶部摘要层是阶段页视觉焦点，但不承担深业务编辑

#### 子入口导航层

这是中间主区最重要的一层，也是本轮确定的核心焦点。该层用于展示阶段内可进入的 3 至 6 个子入口卡片。

每张子入口卡片至少包含：

- 子入口名称
- 一句话用途说明
- 当前状态或可进入提示
- 进入按钮

该层职责是帮助用户快速判断“这一阶段下面可以去哪”，而不是在此处直接完成复杂操作。

#### 阶段内最近活动层

用于承接阶段范围内的：

- 最近任务
- 最近产物
- 最近更新

约束：

- 这里只展示阶段内摘要，不取代完整任务页与产物页
- 最近任务和最近产物必须能跳到真实承接页
- 动态信息保持短摘要，不下沉为长日志列表

### 6.4 右侧栏

右侧栏固定为两段：

#### 上段：阶段助手

展示：

- 当前阶段建议动作
- 快捷跳转
- 常见下一步

#### 下段：下一步建议 / 轻量提示

展示：

- 本阶段输入要求
- 本阶段产出要求
- 风险提醒或规范提示

交互规则：

- 右侧栏必须短、快、可执行
- 不放长篇说明文档
- 点击动作后应进入对应子入口或承接页，而不是在右侧展开重内容

## 7. 六阶段通用壳映射

六个阶段共用同一套页面框架，仅替换阶段数据。

### 7.1 通用字段定义

每个阶段至少提供以下字段：

- `stage_key`
- `stage_label`
- `stage_status`
- `stage_goal`
- `primary_action`
- `entry_cards[]`
- `recent_tasks[]`
- `recent_artifacts[]`
- `assistant_suggestions[]`
- `guidance_notes[]`

Web 与 Desktop 共用同一字段语义，只根据宿主能力调整容器层，不改内容结构。

### 7.2 六阶段内容映射

#### 选题

- 目标：明确研究问题与研究边界
- 子入口建议：
  - 研究问题定义
  - PICO 结构
  - 假设与终点草案
  - 研究设计草案

#### 检索

- 目标：完成检索式与来源配置
- 子入口建议：
  - 检索式管理
  - 数据库来源
  - 检索记录
  - 纳入排除预设

#### 筛选

- 目标：完成文献纳入排除判断
- 子入口建议：
  - 标题摘要筛选
  - 全文筛选
  - 排除原因
  - PRISMA 流程图承接

#### 抽取

- 目标：把非结构化内容转成结构化证据
- 子入口建议：
  - 抽取字段模板
  - 双人抽取
  - 差异处理
  - 证据表

#### 分析

- 目标：组织变量、方法和结果表达
- 子入口建议：
  - 分析变量
  - 统计准备
  - 结果摘要
  - 图表产出

#### 产出

- 目标：形成最终交付产物
- 子入口建议：
  - 方案文档
  - 结果报告
  - 图表附件
  - 导出与版本

## 8. 关键交互规则

### 8.1 阶段页回答的核心问题

阶段页进入后必须优先回答：

- `现在在哪个阶段`
- `这个阶段可以进入哪些能力`
- `下一步建议做什么`

### 8.2 阶段页不承载重业务工作区

本阶段页面不直接承载：

- 大型编辑器
- 复杂表格工作区
- 完整任务系统
- 完整产物版本中心
- 单阶段深业务引擎

这些内容应由阶段页继续向下进入具体子入口页承载。

### 8.3 承接链路要求

`Wave 4` 阶段页必须至少打通以下链路：

- 首页阶段卡片 -> 对应阶段入口页
- 阶段入口页主 CTA -> 当前最优先子入口
- 子入口卡片 -> 对应子功能承接页
- 最近任务 -> 阶段任务承接页
- 最近产物 -> 阶段产物承接页
- 右侧助手建议 -> 对应下一步操作页

### 8.4 项目上下文一致性

阶段页内所有跳转都必须保留同一 `ResearchProject` 上下文，不允许进入阶段页后丢失项目语义，也不允许退化为脱离项目的通用工具页。

## 9. Wave 4 交付边界

`Wave 4` 的重点不是深做单个阶段，而是建立统一、真实、可扩展的阶段入口层。

本波完成后，应达到以下状态：

- 六个阶段都能进入同一套通用阶段壳
- 每个阶段展示不同的标题、目标、子入口卡片、最近任务、最近产物、助手建议
- 阶段页已从骨架页升级为真实入口页
- 首页到阶段页、阶段页到子入口/承接页的链路清楚可达

本波明确不包含：

- 六个阶段对应的所有深业务页实现
- 复杂任务编排与完整负责人系统
- 完整产物版本中心
- 大型分析工作台

## 10. 验收标准

`Wave 4` 完成后，至少应满足：

- 首页阶段卡片可进入统一的阶段入口页
- 六个阶段复用同一通用壳结构
- 每个阶段显示不同的阶段目标和子入口内容
- 中间主区以子入口导航为主，而不是退化成任务表或产物表
- 右侧栏能提供阶段助手和下一步建议
- Web 与 Desktop 呈现一致的阶段页信息架构
- 所有入口都保留统一项目上下文

## 11. 风险与控制点

- 如果阶段页过早深做任务板，范围会迅速膨胀到任务系统建设
- 如果阶段页过早深做产物回看，会偏离“入口枢纽页”的定位
- 如果为每个阶段单独做布局，后续会造成双端和多阶段维护成本急剧上升
- 如果右侧栏承载过重，会再次和中间主区争夺视觉焦点

控制策略：

- 坚持通用阶段壳
- 中间主区坚持子入口导航优先
- 任务和产物只做摘要与承接，不抢主结构
- 右侧栏只做助手与轻量建议

## 12. 设计结论

MedA `Wave 4` 应优先实现 `科研流程模块入口页`，并采用 `阶段入口枢纽` 方案。六个阶段共用一套 `通用阶段壳`，中间主区以 `子入口导航` 为核心，右侧栏固定为 `阶段助手 + 下一步建议`。该设计能够在不拉爆范围的前提下，把 `Wave 3` 首页阶段卡片后的骨架承接页升级为真实可工作的统一入口层，并为后续单阶段深化提供稳定的上层结构。
