## 1. 执行摘要

### 1.1 产品定位

科研全流程 AI-Agent 是一款面向临床科研医生的智能化辅助工具，通过 AI 技术覆盖从文献检索到论文发表的全流程科研活动，帮助医生将原本需要数十小时的科研任务缩短至数小时内完成。

### 1.2 核心价值

- **效率提升**: 文献检索从 20+ 小时缩短至 3 小时内，论文阅读理解时间减少 80%
- **质量保障**: 标准化研究设计方案，降低方法学错误风险
- **成本降低**: 减少对外部咨询服务的依赖，每项目节省 ¥10,000+
- **可及性提升**: 让非统计专业的医生也能独立完成高质量临床研究

### 1.3 目标用户

- **核心用户**: 临床医生（30 万 + 中国三甲医院医生）
- **次要用户**: 科研管理员、医学研究生、临床研究协调员 (CRC)

### 1.4 核心功能模块 (11 个)

1. **R004**: 文献检索与智能去重
2. **R005**: 论文阅读理解
3. **R006**: 多论文对比分析
4. **R007**: 研究方案设计
5. **R008**: 样本量计算
6. **R009**: 课题标书撰写
7. **R013**: eCRF 设计工具
8. **R014**: 临床数据管理平台
9. **R015**: SAP 统计计划生成
10. **R016**: CSR 报告生成
11. **Hook+Loop 核心引擎**: 事件驱动的多 Agent 协作系统

### 1.5 关键技术

- **RAG(检索增强生成)**: 基于向量数据库的智能检索
- **函数调用**: 自动化 API 调用与工具使用
- **多 Agent 协作**: 10+ 专业 Agent 分工协作
- **沙盒代码执行**: 安全的统计计算环境
- **向量数据库**: Milvus 相似度检索

### 1.6 时间规划

**总周期**: 35 天（5 周）  
**交付目标**: v1.0 版本包含核心功能模块（R004-R009）

## 2. 问题陈述

### 2.1 用户痛点

#### 痛点 1: 文献检索耗时过长

**场景描述**: 一位心血管医生需要开展一项"新型降压药 vs 传统药物"的有效性比较研究。按照传统方法，他需要：
- 手动检索 PubMed、CNKI、Wanfang 等多个数据库
- 阅读 200+ 篇摘要，筛选出 50+ 篇全文
- 人工去重相似论文（预计重复率 30%）
- 整理引用格式

**耗时**: 20-40 小时  
**痛点**: 时间成本过高，影响临床工作和研究进度

**用户反馈**: "每次写标书前都要花大量时间查文献，真正做研究的时间被挤占了"（某三甲医院心内科副主任医师，2025 年调研）

#### 痛点 2: 研究方法学错误风险高

**场景描述**: 一位外科医生设计了一项随机对照试验 (RCT)，但：
- 样本量计算错误（未达到 80% 统计效力）
- 纳入排除标准模糊，导致后续筛选困难
- 统计方法选择不当，结果可能无效

**后果**: 研究被审稿人质疑，甚至需要重新招募患者，损失 ¥50,000+

**用户反馈**: "我们医生擅长临床，但方法学是短板，经常因为设计问题被拒稿"（某医科大学附院院长，2025 年访谈）

#### 痛点 3: 标书撰写门槛高

**场景描述**: 申请国家自然科学基金需要：
- 符合特定格式要求（封面、摘要、正文、参考文献）
- 引用最新文献（3-5 篇关键文献）
- 预算合理性论证
- 伦理合规声明

**耗时**: 一位新手需要 2-3 周才能完成初稿，且需反复修改

**用户反馈**: "国自然标书格式复杂，每年都有因为格式问题被形式审查驳回的案例"（某基金委负责人，2025 年分享）

### 2.2 业务影响

#### 若不解决此问题

- **用户流失**: 现有用户因效率低下转向竞品或放弃使用
- **市场机会丧失**: 30 万医生群体中，仅有 5% 能高效开展临床研究
- **收入损失**: 预计首年损失 ¥500 万 + 潜在收入
- **竞争劣势**: 竞品若推出类似功能，将快速抢占市场份额

#### 解决后的商业价值

- **收入增长**: 首年 ARR ¥1,500 万（5,000 付费用户）
- **用户留存**: 6 个月留存率≥60%
- **推荐增长**: NPS≥40，用户自发推荐率提升 30%

### 2.3 证据支持

#### 用户调研数据（2025 年 12 月）

- **样本量**: 20 位三甲医院临床医生
- **方法**: 深度访谈 + 任务观察
- **关键发现**:
  - 85% 的用户表示文献检索是最耗时的环节
  - 70% 的用户曾经历过方法学错误导致的研究返工
  - 60% 的用户认为标书撰写是最大障碍
  - 平均每位医生每年进行 1-2 项临床研究，但仅有 30% 认为"质量满意"

#### 竞品分析

- **竞品 A**: 仅提供文献检索功能，无 AI 生成能力
- **竞品 B**: 侧重论文发表服务，收费高昂（¥50,000+/篇）
- **我们的差异化**: 全流程 AI 辅助，定价亲民（¥1,500/年/用户）

## 4. 非目标 (Non-Goals)

### 4.1 明确排除的功能（v1.0）

#### 4.1.1 PDF 编辑功能

**描述**: 不开发 PDF 的直接编辑能力（如修改文字、插入图片、调整格式）  
**原因**: 
- 技术复杂度超出范围（PDF 解析与编辑是独立领域）
- 用户价值低（用户主要需要读取和提取，而非编辑）
- 法律风险高（可能涉及版权侵权）

**替代方案**: 提供 PDF 下载链接和引用格式导出，用户可手动编辑

#### 4.1.2 论文发表服务

**描述**: 不提供代写、代投、发表保证等服务  
**原因**:
- 伦理风险（学术不端）
- 法律风险（可能涉及欺诈）
- 与产品定位不符（我们是辅助工具，不是替代工具）

**替代方案**: 在文档中明确标注"本工具生成的内容仅供参考，作者需对内容负责"

#### 4.1.3 移动端 App

**描述**: v1.0 不提供 iOS/Android 原生应用  
**原因**:
- 资源限制（开发团队仅 4 人）
- 优先保障 Web 端体验
- 移动端可后期以 H5 形式补充

**替代方案**: Web 端响应式设计，适配平板设备

#### 4.1.4 替代专业统计软件

**描述**: 不替代 SAS、SPSS、Stata 等专业统计软件  
**原因**:
- 功能复杂度差异巨大（专业软件有 30 年积累）
- 用户习惯难以改变（统计师已熟练使用专业工具）
- 我们的定位是"生成统计计划"，而非"执行统计计算"

**替代方案**: 与专业软件形成互补，SAP 生成后可导入专业软件执行

#### 4.1.5 多语言支持（除中文外）

**描述**: v1.0 仅支持中文界面和内容生成  
**原因**:
- 核心用户是中国临床医生
- 中英混合科研场景复杂（文献多为英文，用户为中文）
- 多语言翻译增加工程复杂度

**替代方案**: 后续版本可考虑英文界面，但保持中文生成能力

#### 4.1.6 社交功能

**描述**: 不提供用户社区、论坛、分享等功能  
**原因**:
- 偏离核心需求（用户需要的是工具，而非社交）
- 运营成本高（需维护社区氛围）
- 可能引发数据隐私问题（研究数据泄露）

**替代方案**: 在文档中提供"常见问题"和"用户案例"，以静态内容替代

## 5. 用户故事

### 5.1 P0（必须有）

#### US-001: 文献检索

**作为** 临床科研医生  
**我希望** 输入一个自然语言临床问题（如"二甲双胍 vs 胰岛素治疗 2 型糖尿病的有效性和安全性比较"）  
**以便** 系统自动检索 PubMed/CNKI/Wanfang 数据库，返回 Top 20 相关文献

**验收标准**:
- [ ] 系统能解析 PICO 要素（Population、Intervention、Comparison、Outcome）
- [ ] 支持 PubMed（免费 API）、CNKI（机构账号）、Wanfang（机构账号）
- [ ] 检索响应时间≤3 秒
- [ ] 返回文献包含标题、摘要、作者、期刊、年份、DOI
- [ ] 支持导出 PDF 下载链接和引用格式（GB/T 7714）

#### US-002: 智能去重

**作为** 研究人员  
**我希望** 系统自动识别并去重相似论文  
**以便** 避免重复阅读相同或高度相似的内容

**验收标准**:
- [ ] 向量去重准确率≥90%（基于 Milvus 相似度检索）
- [ ] 标题/摘要去重准确率≥90%（基于编辑距离/Jaccard）
- [ ] 去重后文献数量减少 20%-40%
- [ ] 支持调整去重阈值（宽松/标准/严格）

#### US-003: 论文阅读理解

**作为** 忙碌的医生  
**我希望** 上传 PDF 论文或提供 DOI，系统自动生成结构化摘要  
**以便** 快速了解论文核心发现，无需阅读全文

**验收标准**:
- [ ] 支持中文 PDF 解析，准确率≥95%
- [ ] 结构化摘要包含：背景、方法、结果、结论、局限性、关键数据表
- [ ] 摘要质量医生评分≥4/5 分（盲测）
- [ ] DOI 解析成功率≥90%
- [ ] 响应时间≤5 秒/篇（P95）

#### US-004: 多论文对比

**作为** 研究者  
**我希望** 选择 3-10 篇论文，系统自动生成对比表格  
**以便** 快速了解不同研究的异同点，识别矛盾和一致性

**验收标准**:
- [ ] 提取标准化字段：研究设计、样本量、干预措施、对照、主要结果、效应量
- [ ] 对比表格字段提取准确率≥85%
- [ ] 支持导出 Excel/CSV/PDF
- [ ] 生成综合结论（LLM 生成，准确率≥80%）

#### US-005: 研究方案设计

**作为** 临床医生  
**我希望** 输入研究想法，系统自动生成完整的研究方案草案  
**以便** 快速获得可直接修改的方案，减少从零开始的耗时

**验收标准**:
- [ ] 方案包含 12 个核心章节：标题、背景与意义、研究假设、研究设计、研究对象、样本量计算依据、干预措施、结果指标、统计方法、时间计划、预算估算、局限性与伦理风险
- [ ] 引用文献准确率≥90%（3-5 篇关键文献）
- [ ] 方案可用性≥70%（医生评审可直接使用）
- [ ] 生成时间≤30 秒/份

#### US-006: 样本量计算

**作为** 研究者  
**我希望** 选择研究设计类型（两组均值比较、两组率比较、生存分析等），输入参数后自动计算所需样本量  
**以便** 避免样本量不足导致的统计效力问题

**验收标准**:
- [ ] 支持 5 种以上设计类型：均值比较、率比较、生存分析、相关分析、方差分析
- [ ] 计算结果与 G*Power 一致（对比 50 个案例）
- [ ] 参数验证友好（错误输入给出清晰提示）
- [ ] 结果解释清晰（中文说明，非仅数字）
- [ ] 响应时间≤1 秒/次

#### US-007: 标书撰写

**作为** 申请国自然的医生  
**我希望** 基于研究方案，系统自动生成符合国家自然科学基金格式要求的标书草案  
**以便** 减少格式调整时间，专注于内容优化

**验收标准**:
- [ ] 格式 100% 符合国自然模板要求
- [ ] 所有必填项齐全（自动检查）
- [ ] 可用草案比例≥60%（可直接提交）
- [ ] 生成时间≤1 分钟/份
- [ ] 修改次数平均≤3 次

#### US-008: eCRF 设计

**作为** 临床研究协调员  
**我希望** 通过可视化界面设计电子病例报告表（eCRF）  
**以便** 快速生成符合 CDISC 标准的数据采集表单

**验收标准**:
- [ ] 支持所有常用字段类型：单选、多选、填空、日期、数值、文本
- [ ] 导出符合 CDISC ODML 标准
- [ ] 设计响应时间≤2 秒/次操作
- [ ] 支持多人协作编辑
- [ ] 支持历史版本回滚

#### US-009: 数据管理

**作为** 数据管理员  
**我希望** 在平台上录入和质控临床研究数据  
**以便** 确保数据质量和完整性

**验收标准**:
- [ ] 数据上传效率≥50 条/小时
- [ ] 支持 20 种以上质控规则（范围检查、逻辑检查、一致性检查）
- [ ] 审计追踪完整（100% 操作记录）
- [ ] 数据锁定后不可修改（安全机制）
- [ ] 支持 Excel/CSV 导入导出

#### US-010: SAP 生成

**作为** 统计师  
**我希望** 基于研究方案自动生成统计分析报告（SAP）草案  
**以便** 减少重复性工作，专注于方法学设计

**验收标准**:
- [ ] 完整性符合 ICH E9 标准
- [ ] 统计方法 100% 正确（统计师审核）
- [ ] 生成时间≤30 秒/份
- [ ] 所有段落可编辑

#### US-011: CSR 报告生成

**作为** 临床研究员  
**我希望** 统计分析完成后自动生成临床总结报告（CSR）  
**以便** 快速形成最终报告，节省撰写时间

**验收标准**:
- [ ] 完整性符合 ICH E3 标准
- [ ] 图表数据 100% 正确（数据核对）
- [ ] 生成时间≤2 分钟/份
- [ ] PDF 质量符合出版标准

| 风险 ID | 风险描述 | 概率 | 影响 | 缓解措施 | 负责人 |

1. 立即停止服务
2. 修复漏洞并进行安全审计
