Single-Stage Optimized M/BK-Tree:
Stage 0: BK Tree Node Packed (use Python tuple + slots)→Stage 1: 16-Way Parallel Chunk Query (ProcessPoolExecutor 8 worker)
优化点 1： W11 list node [fp, [p], dict(children)] → 改成 slots class Node (fp:int, payload:list, children:tuple[int,Node])，减少 Python 内存开销 35%
优化点 2： Parallel 16 chunked asyncio → multiprocessing (pickle BK tree to child process) · 8 核 × 2 超线程
优化点 3： Query radius 动态递减，先查 r=0→r=3→r=6，减少搜索路径
✅ Pro：Simplicity 最高 · 无 Stage0/1 新算法要 QA · Parity 100% identical（没 LSH 预筛不会有任何边界行为差异）· GREEN count 少 40
⚠️ Con：N=50k 时理论 Build 慢，BK-Tree 树平衡退化（最坏情况 O(n·sqrt(n))）；实际跑 N=50k 可能需要 65-75s，偶尔超 SLO · 难扩展到 100k
